# 菜单权限实时刷新设计

## 目标

角色菜单授权、用户角色分配和菜单定义变化后，在线 Web 会话无需重新登录即可获得最新菜单与按钮权限；前端同时提供主动刷新入口。

## 方案

沿用现有 `/sys/menu/routes` 全量权限接口和用户消息 SSE 连接，新增 `permission-changed` 事件。后端在权限相关事务提交成功后向租户在线用户广播变更事件，避免事务回滚时误刷新。前端在 `MainLayout` 的 SSE 连接中监听该事件，使用静默请求重新拉取 routes、buttons、modules，清理旧动态路由并重新注入；请求去重，连续事件只触发一次刷新。

手动刷新复用同一刷新函数，入口放在现有用户菜单中，显示刷新状态。刷新失败保留当前权限与路由，避免短暂网络故障造成用户被错误踢出；当前页面被撤权时回到个人主页，并清理已撤权标签。

## 事件与一致性

- 事件名：`permission-changed`。
- 事件数据：`tenantId`、`reason`、`timestamp`，不携带权限内容，权限始终从鉴权接口读取。
- 广播范围：发生变更的租户。这样覆盖角色授权、用户角色绑定和菜单定义变化，牺牲少量无关刷新换取实现完整性和跨用户正确性。
- 后端发布通过事务 `afterCommit` 执行；无事务场景立即发布。
- 前端刷新成功后更新 Pinia、路由和本地缓存；刷新失败不清空旧缓存。

## 影响范围

- 后端：SSE 权限变更通知器、Web 菜单服务、角色菜单服务、用户角色服务。
- 前端：SSE hook 支持自定义事件、路由刷新 API、权限 store 清理/版本处理、主布局自动与手动刷新入口及多语言文案。

## 验证

- 前端 `npm run build`。
- 后端 `mvn -q -DskipTests compile`。
- 静态回归检查：授权接口提交后只在事务成功时发布事件；SSE 断线自动重连不影响手动刷新；撤权当前路由回退到个人主页。
