# 内部服务接口说明

> 分类：开发规范 / 后端契约
> 版本：**V1.0.0**

本文只规定 Forgex 服务之间的内部接口契约。第三方接入另见[第三方接口平台说明](./第三方接口平台说明.md)。

## 模块归属

| 内容 | 模块 |
|---|---|
| 共享 DTO | `Forgex_Domain_Contract` |
| Feign Client | 提供方 `Forgex_{服务}_Api` |
| 统一返回 | `Forgex_Common_Contract` 的 `R<T>` |
| Token、租户、语言透传 | `Forgex_Common_Web` 自动配置 |

`Forgex_Common` 是兼容聚合壳，新契约不得继续放入该模块源码。

## 实现步骤

1. 在 `Forgex_Domain_Contract` 定义跨服务 DTO。
2. 在提供方 `*_Api` 定义 Feign Client，方法使用 `@PostMapping` 和 `@RequestBody`。
3. 提供方 Controller 返回 `R<T>`，业务逻辑仍按 `controller -> service -> mapper` 分层。
4. 消费方只依赖对应 `*_Api`、Domain Contract 和 Common Contract，不依赖提供方实现模块。

## 代码示例

现有工作流契约：

```java
@FeignClient(name = "forgex-workflow")
public interface WorkflowExecutionFeignClient {
    @PostMapping("/wf/execution/internal/timeout/scan")
    R<Boolean> scanTimeoutInstances(@RequestBody WorkflowTimeoutScanRequestDTO request);
}
```

新增接口前必须从提供方 Controller 核对路径、请求 DTO 和返回 VO，并补 Feign 单元测试或契约测试。
