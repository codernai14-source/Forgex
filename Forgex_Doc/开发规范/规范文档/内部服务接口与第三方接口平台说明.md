# 内部服务接口与第三方接口平台说明

> 适用范围：Forgex 体系内服务间接口契约与第三方接入边界
> 版本：**V0.8.5**
> 更新时间：**2026-08-12**

本文用于统一说明两类接口的边界：

- **内部服务接口**：Forgex 各业务模块之间互相调用的接口契约
- **第三方接口平台**：外部系统接入 Forgex 的统一入口，走 `Forgex_Integration`

两者不要混写，也不要混用同一套文档入口。

> 模块拆分后的依赖选型详见：[Common 模块化拆分与二开指南](../../后端/公共能力/Common模块化拆分与二开指南.md)。

## 一、内部服务接口怎么定义

### 1.1 存放位置（Maven 归属）

| 内容 | Maven 模块 | Java 包名（可保持） |
|---|---|---|
| 共享 DTO | `Forgex_Domain_Contract` | `com.forgex.common.api.dto` |
| 必要共享注解 | `Forgex_Domain_Contract` | `com.forgex.common.api.annotation` |
| Feign Client | 提供方 `Forgex_{服务}_Api` | `com.forgex.common.api.feign` |
| Feign Token 透传 / Web 自动配置 | `Forgex_Common_Web` | `com.forgex.common.feign` 等 |
| 运行时 Aspect / 示例 | `Forgex_Common_Infra` | `com.forgex.common.api.aspect` 等 |

说明：

- **不要再把新契约塞回单体 `Forgex_Common` 源码树**（该模块已变为兼容聚合，无实现源码）。
- 包名可暂不重命名，优先保证 Maven 边界正确。

### 1.2 命名原则

- DTO 命名要体现业务对象，例如 `MaterialAggregateDTO`、`UserInfoDTO`、`WorkflowTimeoutScanRequestDTO`
- Feign Client 命名要体现“谁提供能力、谁被调用”，例如 `SysUserFeignClient`、`WorkflowExecutionFeignClient`
- 方法命名要直接表达查询动作，例如 `getById`、`listByCodes`、`resolveSuperiorUserIds`、`scanTimeoutInstances`

### 1.3 返回约定

- 内部服务接口优先返回统一包装 `R<T>`（来自 `Forgex_Common_Contract`）
- 单条接口返回对象，批量接口返回集合
- 查询条件复杂时，优先封装请求 DTO，不直接堆一串方法参数

### 1.4 注解约定

- Controller、DTO、Param、VO 都要补齐 `@Tag`、`@Operation`、`@Schema`
- 内部服务契约也要保持接口说明清楚，方便联调和接口文档生成

## 二、内部服务接口和第三方接口平台的区别

### 2.1 内部服务接口

- 服务对象是 Forgex 体系内其他模块
- 调用方式以 Feign、内部 Controller 契约为主
- 重点是稳定、清晰、批量友好
- 不承载第三方系统认证、参数转换、回调编排

### 2.2 第三方接口平台

- 服务对象是 Forgex 体系外部系统
- 统一走 `Forgex_Integration`
- 重点是接入配置、授权、映射、审计、调用日志、结果追踪
- 不要把第三方系统的开放接口直接塞进业务模块内部契约

## 三、推荐的接口开放流程

1. 先确认接口是“模块互调”还是“第三方接入”
2. 如果是模块互调：
   - 共享 DTO 放入 `Forgex_Domain_Contract`
   - Feign Client 放入提供方 `Forgex_{服务}_Api`
3. 再由对应业务模块实现 Controller 与 Service
4. 接口路径、请求体、返回体保持和契约一致
5. 消费方 POM **只依赖该 Api + Domain_Contract + Contract**，不要依赖 `Forgex_Common` 聚合
6. 用 API 文档注解补齐说明，保证其他模块可以直接按文档调用

## 四、调用内部服务接口的建议

- 优先依赖提供方 `*_Api` 下的 Client，不自己手写重复 HTTP 调用
- 能批量就批量，减少频繁远程请求
- 调用方只关心契约，不直接依赖提供方内部实现细节
- 需要用户、物料、供应商、客户、部门、职位、角色等主数据时，优先走公共契约，不重复查库
- `*_Api` 之间禁止互相依赖；共享模型下沉到 `Forgex_Domain_Contract`

## 五、第三方接入的文档边界

- 第三方系统接入说明继续保留在 `Forgex_Doc/后端/模块专题/集成平台.md`
- 第三方系统的参数映射、签名、回调、调用日志和错误处理，不放进内部服务接口规范
- 如果某个接口既要给内部模块用，又要给外部系统用，应该拆成两套入口，分别归属内部契约和接口平台
