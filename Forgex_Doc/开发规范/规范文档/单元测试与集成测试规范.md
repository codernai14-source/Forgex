# 单元测试与集成测试规范

> 版本：**V0.8.5**

本规范用于补齐 Forgex 前端、后端和接口联调的最低测试要求。已有 AI 自动化测试手册偏向辅助执行，本规范用于约束日常开发、提交前自检和缺陷修复验证。

## 一、测试分层

| 层级 | 目标 | 典型验证 |
|---|---|---|
| 单元测试 | 验证函数、Service、小组件的局部逻辑 | 参数校验、分支、异常、工具方法 |
| 集成测试 | 验证模块之间协作 | Controller-Service-Mapper、缓存、消息、文件、权限 |
| 接口测试 | 验证 HTTP 合同 | 路径、方法、请求体、响应结构、状态码 |
| E2E 测试 | 验证用户流程 | 登录、菜单、列表查询、新增编辑、权限按钮 |

## 二、后端测试要求

- Service 层新增复杂业务逻辑时，应覆盖成功、失败、边界和异常分支。
- Controller 接口变更时，应验证统一返回结构、权限、租户上下文和参数校验。
- Mapper 或 XML SQL 变更时，应验证查询条件、分页、排序和逻辑删除。
- 缓存、SSE、RocketMQ、工作流等横向能力变更时，应增加集成验证或明确手工验证步骤。
- 数据库脚本变更必须在开发库或测试库执行验证，并准备回滚说明。

## 三、前端测试要求

- 新增页面至少验证构建通过、路由可进入、接口请求正确、主要交互可用。
- 新增 i18n 文案后运行 i18n 检查，确保五语言 key 结构一致。
- 表单页面验证必填、格式、重置、编辑回显和提交失败提示。
- 权限按钮验证有权限显示、无权限隐藏，并确认后端接口仍会鉴权。
- 动态表格页面验证列配置、查询、分页、列设置保存和恢复。

## 四、提交前命令

前端常用命令：

```powershell
npm run build
npm run i18n:audit
```

后端常用命令：

```powershell
mvn test
mvn -pl <module> test
```

如果仓库当前没有完整自动化测试，应运行最小可行验证命令，并在交付说明中写明未覆盖的风险。

## 五、缺陷修复验证

缺陷修复必须覆盖复现路径：

1. 记录修复前触发条件。
2. 验证修复后的正常路径。
3. 验证相邻路径没有回归。
4. 涉及文档或配置时同步更新对应说明。

## 六、验收标准

- 关键命令执行通过，或明确说明无法运行的原因。
- 新增/变更接口有接口文档或注解说明。
- 前后端字段、权限编码、路由、菜单和 i18n key 对齐。
- 数据库、缓存、消息、文件等外部依赖有可重复验证步骤。
