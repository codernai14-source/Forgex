# TDE透明加密使用方式

> 分类：数据库 / 安全与配置
> 版本：**V1.0.0**

## 源码和接入方式

当前仓库没有 Forgex 代码可直接调用的 TDE API，也没有自动启用脚本。使用者是 DBA/运维，接入点是目标 MySQL 或云数据库的管理面；应用仍按 [加密功能使用方式](../../后端/模块专题/加密功能使用方式.md) 处理字段级加密。

## 评估示例

```sql
-- 仅供 DBA 在目标实例核对，Forgex 不执行此语句
SHOW VARIABLES LIKE '%encrypt%';
```

实施前应确认数据库版本、存储引擎、KMS、密钥轮换、备份恢复和跨区迁移策略，并在副本环境做性能基线。TDE 保护数据库文件，不能替代应用层字段脱敏或传输加密。

## 错误排查和推荐

- 恢复后无法解密：检查备份是否包含密钥材料、KMS 权限和密钥版本。
- 性能下降：比较加密前后 IO、CPU、慢查询和备份窗口。
- 误以为已全链路保护：继续核对应用层敏感字段、日志脱敏和 TLS。
- 推荐先完成演练记录，再安排生产切换；当前产品不会替 DBA 回滚 TDE。
