# 数据库设计规范

> 版本：**V0.6.5**

本规范补齐 Forgex 数据库设计、索引、SQL 变更和迁移回滚口径。字段命名和统一字段以 [数据库字段统一规范文档](../../开发规范/规范文档/数据库字段统一规范文档.md) 为准；本文聚焦表结构设计和变更执行。

## 一、表设计

- 表名使用小写字母和下划线，必须带模块前缀，例如 `sys_`、`fx_`、`biz_`。
- 主键统一使用 `id bigint`，由项目雪花算法或统一主键策略生成。
- 业务表必须包含创建、更新、逻辑删除等通用字段。
- 需要租户隔离的表必须包含 `tenant_id`。
- 所有字段必须有 `COMMENT`，注释描述业务含义，不只重复字段名。
- 存储引擎统一使用 InnoDB，字符集使用 utf8mb4。

## 二、字段类型

| 场景 | 推荐类型 |
|---|---|
| 主键、外键 | `bigint` |
| 状态、类型、开关 | `tinyint` |
| 金额、精确小数 | `decimal` |
| 普通名称 | `varchar(100)` 或按字段规范 |
| 编码、账号 | `varchar(50)` |
| 长文本 | `text` |
| 业务时间 | `datetime` |
| 扩展配置 | `json` 或 `text`，按 MySQL 版本和兼容性决定 |

敏感字段应结合加密功能文档评估是否需要应用层加密、脱敏展示或 TDE 保护。

## 三、索引策略

- 主键必须存在。
- 业务唯一约束使用 `uk_字段名` 或 `uk_表名_字段名`。
- 普通索引使用 `idx_字段名`。
- 联合索引字段顺序按等值条件、范围条件、排序字段综合设计。
- 多租户高频查询优先评估 `tenant_id + 业务字段` 联合索引。
- 分页排序字段应结合 WHERE 条件评估索引。
- 避免重复索引和低选择性无效索引。

## 四、SQL 编写

- SELECT 指定字段列表，不使用 `SELECT *`。
- UPDATE、DELETE 必须带明确 WHERE 条件。
- 业务删除默认使用逻辑删除。
- 分页查询必须带 ORDER BY。
- JOIN 使用显式 JOIN，并补齐关联字段索引。
- 禁止拼接 SQL，优先使用 MyBatis-Plus、MPJ 或 XML 参数化 SQL。

## 五、数据迁移与升级

数据库升级脚本应满足：

1. 文件名能体现日期、模块和变更目的。
2. DDL、DML 逻辑清晰，避免混入无关变更。
3. 执行前备份目标库。
4. 先在开发或测试环境验证。
5. 对破坏性变更准备回滚 SQL 或手工回滚步骤。
6. 交付包升级脚本按文件名顺序执行。

脚本放置位置应遵循当前交付流程：正式交付升级脚本由构建工程收集到 `database-upgrade/`，过程性排查脚本放 `doc/`，正式说明沉淀到 `Forgex_Doc/数据库/脚本与修复`。

## 六、ER 关系说明

当前文档不维护独立图片式 ER 图。新增模块应在模块专题或数据库说明中用表格描述核心关系：

| 主表 | 关联表 | 关系 | 说明 |
|---|---|---|---|
| `sys_user` | `sys_user_role` | 一对多 | 用户与角色授权关系 |
| `sys_role` | `sys_role_menu` | 一对多 | 角色与菜单/按钮权限关系 |

涉及跨库、跨服务或历史表时，应额外说明数据来源、同步方式和一致性边界。

## 七、设计检查清单

- 表名、字段名、索引名符合规范。
- 通用字段和租户字段齐全。
- 字段类型、长度、默认值和注释合理。
- 高频查询有索引支撑。
- SQL 脚本可重复审阅，执行顺序清晰。
- 有升级验证和回滚说明。
