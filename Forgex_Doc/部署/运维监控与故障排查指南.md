# 运维监控与故障排查指南

> 版本：**V0.6.6**

本文补齐 Forgex 部署后的运行监控、日志定位和常见故障排查口径。客户环境应优先使用安装目录内的控制中心、脚本和日志目录定位问题，不在文档中记录生产密码或敏感配置。

## 一、服务健康检查

| 服务 | 默认端口 | 关注点 |
|---|---|---|
| Gateway | 9000 | 网关启动、路由转发、鉴权、Nginx `/api/` 代理 |
| Auth | 9001 | 登录、验证码、Token、租户选择 |
| Sys | 9002 | 用户、角色、菜单、字典、文件、系统配置 |
| Basic | 9003 | 基础资料、物料、供应商 |
| Job | 9004 | 定时任务和异步执行 |
| Workflow | 9005 | 审批配置和执行 |
| Integration | 9007 | 第三方系统和 API 调用 |
| Report | 9006 | 报表设计和预览 |

服务启动后先确认端口监听、注册中心状态和日志中无启动异常。

## 二、日志目录

部署文档约定日志根目录由 `FORGEX_LOG_DIR` 或 `forgex.deployment.log-dir` 控制。Windows 安装默认位于安装目录下 `logs`，常见子目录包括 `gateway`、`auth`、`sys`、`basic`、`job`、`workflow`、`integration`、`report`、`nginx`。

排查时优先查看：

1. 控制中心错误日志。
2. 目标服务启动日志。
3. 网关日志。
4. Nginx 日志。
5. MySQL、Redis、RocketMQ、Nacos 自身日志。

## 三、常见故障

| 现象 | 排查方向 |
|---|---|
| 前端能打开但接口 404 | 检查 Nginx `/api/` proxy_pass 是否保留 `/api` 前缀，检查网关路由 |
| 登录失败 | 检查 Auth 日志、验证码配置、Redis、租户数据、Token 配置 |
| 菜单为空 | 检查 Sys/Auth 菜单接口、角色授权、前端动态路由缓存 |
| 服务启动失败 | 检查端口占用、Nacos 配置、数据源、Redis、RocketMQ、授权文件 |
| 文件上传失败 | 检查上传目录、磁盘权限、系统配置和访问地址 |
| 字典或配置不刷新 | 检查 Redis、Caffeine 本地缓存失效、服务实例是否收到失效消息 |

## 四、中间件检查

- Nacos：确认命名空间、分组、dataId 与部署环境一致。
- MySQL：确认数据库已初始化，账号权限满足业务读写，慢查询日志可用。
- Redis：确认地址、密码、数据库编号和网络连通。
- RocketMQ：确认 NameServer、Broker、topic 和消费组状态。
- Nginx：确认静态目录、前端端口、网关代理和 mime 配置。

## 五、扩缩容注意事项

- 多实例部署时，各服务必须连接同一套 Nacos、Redis、RocketMQ 和数据库。
- 本地缓存依赖 Redis 失效通知实现最终一致，扩容后要确认实例能正常订阅消息。
- 文件上传如果使用本地磁盘，多实例需要共享存储或统一对象存储。
- 定时任务和异步任务扩容时要确认是否存在重复执行风险。
- 网关和前端 Nginx 扩容后要确认会话、跨域和代理路径一致。

## 六、问题记录模板

排查生产问题时建议记录：

- 环境、实例编码、服务版本。
- 触发时间和用户操作路径。
- 前端 Network 请求路径、状态码、响应体。
- 网关和目标服务日志片段。
- 中间件状态。
- 临时处理动作和最终修复结论。
