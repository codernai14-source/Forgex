# 在线开发/代码生成增强计划

## Summary
- 修复 Forgex 在线开发生成结果里的权限码、菜单 SQL、路径和模板不一致问题。
- 增强字段配置：支持字典下拉、接口下拉、接口树形下拉；接口型字段可在前端配置接口地址、请求方法、传参、响应路径和字段映射。
- 字典字段按后端规范生成 VO：原字段保留原值，新增转换后字段，并使用现有 `@DictI18n` 自动转换。
- 默认不改 `fx_table_column_config` 表结构，选项源配置存入代码生成配置 JSON，由生成页面加载。

## Key Changes
- 扩展字段配置契约：`ColumnMetaDTO` 和前端 `CodegenColumnConfig` 新增 `optionSourceType`、`optionApiUrl`、`optionApiMethod`、`optionParamsJson`、`optionResponsePath`、`optionLabelField`、`optionValueField`、`optionChildrenField`，默认 `GET`、`data`、`label`、`value`、`children`。
- 配置抽屉新增“选项源”配置：字典类型选择 `dictCode`；接口类型可配置接口地址、方法、固定参数 JSON、响应数组路径；树形接口额外配置 children 字段。
- 后端模板新增 VO 生成：字典字段生成 `@DictI18n(nodePathConst = "<dictCode>", targetField = "<field>Text")`，并新增 `private String <field>Text;`；服务层 `page/detail/tree` 返回 VO，不再直接返回 Entity。
- 服务模板增加 Entity 到 VO 的映射：使用 `BeanUtils.copyProperties`，分页、详情、树形、主子表都返回对应 VO；新增/修改入参仍使用 SaveParam。
- 前端生成模板使用 VO 的 `<field>Text` 优先展示字典标签；接口下拉/API树形下拉由生成页面在 `onMounted` 或依赖参数变化时加载 options，并归一化为 `{ label, value, children }`。
- 权限和 SQL 模板统一：活跃策略模板 `single/master-detail/tree-single/tree-double` 全部对齐 `v-permission`、`@RequirePerm`、`sys_menu.perm_key`；SQL 使用 `forgex_admin` 写菜单权限，`forgex_common` 写表格配置、国际化和响应消息。

## Test Plan
- 后端运行 `mvn -pl Forgex_Sys -am test`，新增模板渲染断言：字典字段生成 VO 注解和 `<field>Text`，服务返回类型为 VO。
- 前端运行 `npm run build`，验证配置抽屉、类型定义和生成模板编译通过。
- 生成单表、主子表、树单表、树双表样例，覆盖字典字段、接口下拉、接口树形下拉。
- 检查生成代码无旧权限后缀 `add/edit/query/view`，权限码和 SQL 完全一致。
- 执行或语法检查生成 SQL，确认 `forgex_admin/forgex_common` 目标库和字段形状正确。

## Assumptions
- 字典转换使用 Forgex 已有 `com.forgex.common.dict.DictI18n` 和 `RDictI18nAdvice`，转换后字段统一命名为 `<原字段名>Text`。
- 接口下拉配置由生成页面前端直接调用接口，不新增后端 provider 注册表。
- `optionParamsJson` 只保存静态 JSON 参数；字段联动参数后续可扩展为依赖字段配置。
