# 权限指令实现逻辑

> 版本：`V0.8.5`

权限指令实现位于 `src/directives/permission.ts`，并在应用初始化时注册为 `v-permission`。

## 一、判断函数

指令内部通过 `use权限Store()` 获取权限 store，再调用 `has权限` 判断权限编码是否存在。由于 Pinia setup store 在实例上会自动解包 computed，当前实现同时兼容函数和 `computed.value` 两种形态。

## 二、挂载行为

`mounted` 阶段会记录元素原始 `display`：

```ts
(el as any).__v权限OriginalDisplay = originalDisplay
```

如果绑定值存在且用户无权限，元素设置为 `display: none`。如果拥有权限，则恢复原始 display。

## 三、更新行为

`updated` 阶段重新读取绑定值并再次判断权限。这样在权限列表异步恢复、路由重新注入或组件重新渲染后，按钮显示状态能跟随最新权限变化。

## 四、设计边界

- 当前指令采用隐藏元素策略，不销毁组件实例。
- 指令只接收单个权限字符串；多个权限组合应在组件脚本中通过 `permissionStore.hasAny权限` 或 `hasAll权限s` 计算后控制渲染。
- 权限判断依赖前端缓存的按钮权限，只作为用户体验优化。
- 安全边界在后端，后端接口仍需独立校验权限。
