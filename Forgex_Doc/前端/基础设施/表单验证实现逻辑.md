# 表单验证实现逻辑

> 版本：`V0.6.5`

表单验证分散在各页面和公共弹窗中，统一依赖 Ant Design Vue Form 能力。项目常见实现包括 `rules`、`computed rules`、`FormInstance.validate`、`validateFields`、`clearValidate`。

## 一、表单实例

页面通过 `ref<FormInstance>()` 保存表单实例：

```ts
const formRef = ref<FormInstance>()
```

提交时调用 `await formRef.value?.validate()`。校验失败时 Ant Design Vue 会阻断后续提交逻辑，并在对应 `a-form-item` 上展示错误。

## 二、规则来源

项目内主要有三类规则来源：

- 页面内固定规则：如角色、部门、岗位、租户等管理页。
- 计算规则：如注册、邀请码、菜单等依赖 i18n 或动态状态的页面。
- 配置规则：如代码生成、动态表格、导入导出、低代码表单等根据配置生成或分组校验。

## 三、校验执行点

校验通常出现在：

1. 保存按钮点击。
2. 下一步或测试连接前的局部字段校验。
3. 弹窗确认回调。
4. 动态配置提交前的多表单联合校验。

多表单页面应按业务顺序依次校验，例如基础信息表单通过后再校验明细配置表单。

## 四、错误展示与清理

Ant Design Vue 负责字段级错误展示。弹窗关闭、表单重置、切换编辑对象时，应同步清理表单数据和校验状态，避免上一条数据的错误带到下一次编辑。

## 五、后端兜底

前端校验只保证交互及时性。所有必填、唯一性、权限、租户隔离和业务状态校验必须在后端继续执行，并通过统一返回与国际化提示链路反馈给前端。
