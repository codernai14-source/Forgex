# 状态管理实现逻辑

> 版本：`V0.6.5`

状态管理入口位于 `src/stores/index.ts`，所有 store 采用 Pinia setup store 写法，并按职责拆分。当前实现没有启用 Pinia 持久化插件，而是在关键 store 内显式读写 `sessionStorage` 或 `localStorage`。

## 一、用户状态

`useUserStore` 管理当前用户信息：

- `userInfo` 保存账号、用户名、头像、邮箱、手机号、租户等基础信息。
- `setUserInfo` 同步写入 `sessionStorage.account` 和 `sessionStorage.tenantId`。
- `restoreFromSession` 页面加载时先用会话信息快速恢复，再调用个人信息接口刷新后端最新数据。
- `logout` 调用后端登出接口后清理本地用户信息。

## 二、权限与动态路由状态

`use权限Store` 同时管理按钮权限、动态路由和模块：

- `permissions` 用于按钮级权限判断。
- `routes`、`modules` 保存后端返回的菜单路由和模块列表。
- `setRoutes`、`setModules` 将动态路由缓存到 localStorage。
- `restoreRoutesAndModules` 读取缓存前校验 `ROUTE_CACHE_VERSION`，版本不一致时清空旧缓存。
- `clear权限s` 同时清理按钮权限、动态路由、模块和缓存版本。

## 三、应用级状态

`useAppStore` 管理横向 UI 状态：

- `sidebarCollapsed` 控制侧边栏折叠。
- `theme` 保存浅色/暗色主题标识。
- `locale` 保存当前语言，并通过 `setI18nLocale` 同步到 i18n。
- `loading` 保存全局加载状态。
- `formMode` 统一记录公共表单默认展示模式，当前支持 `modal` 和 `drawer`。

## 四、初始化链路

1. `main.ts` 注册 Pinia。
2. store 被首次使用时执行 setup 初始化。
3. 用户 store 从 sessionStorage 恢复账号和租户。
4. 权限 store 从 sessionStorage 恢复按钮权限。
5. 路由守卫在需要时调用 `permissionStore.restoreRoutesAndModules()` 恢复动态路由缓存。

## 五、设计边界

- Store 只保存需要跨页面共享的状态，不承载页面表格查询条件等局部状态。
- Store 不直接发起与自身职责无关的业务请求。
- 与安全相关的状态只能作为前端展示控制依据，最终接口权限仍以后端鉴权为准。
