# 路由与菜单实现逻辑

> 版本：`V0.6.5`

路由核心实现位于 `src/router/index.ts`。系统基础页面以静态路由注册，业务菜单页面由后端返回后动态注入到 `Workspace` 路由下。

## 一、静态路由

静态路由负责不依赖菜单权限的基础入口：

- `/login`、`/register`、`/init` 直接放行。
- `/workspace` 使用 `MainLayout`，内置个人首页、收藏管理、个人信息、系统配置等基础子路由。
- `/redirect` 支持带 `to` 参数的内部重定向。
- 历史审批路径通过守卫重定向到新的审批路径。

## 二、路由守卫

全局 `beforeEach` 执行以下流程：

1. 放行登录、注册、初始化页面。
2. 未登录或缺少租户信息时跳转 `/login`。
3. 工作区未知子路径先命中 `WorkspaceNotFound` 待恢复路由，不立即跳转 404。
4. 动态路由为空或命中待恢复路由时，先从 `permissionStore.restoreRoutesAndModules()` 恢复缓存。
5. 缓存为空或恢复后仍未匹配目标地址时，调用 `getRoutes({ account, tenantId })` 从后端拉取路由、模块和按钮权限。
6. 调用 `injectDynamicRoutes` 注入路由后重新进入目标地址。
7. 访问 `/workspace` 根路径时重定向到个人首页。

## 三、动态注入

`injectDynamicRoutes` 会先清理上一次注入的动态路由，再处理新的 routes/modules：

- `dynamicModules` 保存模块列表，供布局模块菜单使用。
- `dynamicRoutes` 保存后端菜单树，供布局渲染菜单使用。
- `injectedRouteNames` 记录已注入路由名，避免重复注册。
- catalog 节点不注册页面路由，只递归处理其子菜单。
- 本地隐藏页通过 `localModuleRoutes` 补充，适合审批节点配置、补偿中心等不直接出现在菜单中的页面。

## 四、组件解析

`loadComponent` 按优先级解析组件：

1. 审批模块固定组件映射。
2. 标签等特殊组件映射。
3. 常用稳定组件映射。
4. 基于模块编码和组件 key 的约定式路径推导。
5. 基于路由静态片段的路径推导。
6. 找不到时返回 `EmptyView`，避免路由注册失败导致整页崩溃。

## 五、缓存策略

动态路由与模块缓存存放在 localStorage，并由 `ROUTE_CACHE_VERSION` 控制兼容性。后端菜单结构、组件 key 或前端页面目录有破坏性调整时，应同步更新缓存版本，确保用户重新拉取最新路由。

## 六、缺省状态页

工作区内置 `/workspace/fallback/:kind` 静态缺省页，支持 `403`、`404`、`offline` 三类状态。该路由挂载在 `Workspace` 子路由下，并在守卫中直接放行，确保动态菜单尚未恢复或接口不可用时仍可展示兜底页面。

全局未知路径重定向到 `/workspace/fallback/404`。工作区未知子路径先进入 `WorkspaceNotFound` 待恢复路由，由守卫恢复动态菜单路由并重试原地址；缓存恢复和后端强制刷新都失败后，才跳转到 `/workspace/fallback/404`。缺省页文案使用 `fallback.*` 国际化命名空间，样式位于 `src/styles/views/fallback/index.less`，页面组件位于 `src/views/fallback/index.vue`。
