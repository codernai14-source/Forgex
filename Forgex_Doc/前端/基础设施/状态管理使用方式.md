# 状态管理使用方式

> 版本：`V0.8.5`

Forgex 前端使用 Pinia 管理跨组件状态，统一从 `src/stores/index.ts` 导出。页面应通过已有 store 读取登录态、权限、布局和实时消息状态，避免在业务组件中重复维护全局副本。

## 一、可用 Store

| Store | 入口 | 主要用途 |
|---|---|---|
| `useUserStore` | `src/stores/user.ts` | 当前用户、账号、租户、登出、会话恢复 |
| `use权限Store` | `src/stores/permission.ts` | 按钮权限、动态路由、模块缓存 |
| `useAppStore` | `src/stores/app.ts` | 侧边栏、主题、语言、全局加载、表单展示模式 |
| `useGuideStore` | `src/stores/guide.ts` | 页面引导状态 |
| `useSseStore` | `src/stores/sse.ts` | SSE 连接和消息推送状态 |

## 二、页面中使用

```ts
import { useUserStore, use权限Store, useAppStore } from '@/stores'

const userStore = useUserStore()
const permissionStore = use权限Store()
const appStore = useAppStore()

const account = userStore.account
const canAdd = permissionStore.has权限('sys:user:add')
appStore.setLoading(true)
```

使用 setup store 时，Pinia 会自动解包 `ref` 和 `computed`。模板里可直接访问 store 属性；脚本中如需解构响应式字段，优先使用 `storeToRefs`。

## 三、持久化边界

1. 登录基础信息保存到 `sessionStorage`，包括 `account`、`tenantId`。
2. 按钮权限保存到 `sessionStorage.permissions`。
3. 动态路由和模块保存到 `localStorage.fx-dynamic-routes`、`localStorage.fx-dynamic-modules`，并带 `fx-dynamic-routes-version` 版本号。
4. 用户登出或租户切换时必须清理权限和动态路由缓存，避免残留菜单影响下一次登录。

## 四、使用约定

- 新增全局状态前先判断是否属于已有 store 的职责；页面内临时状态保留在组件中。
- 权限判断统一走 `use权限Store` 或 `v-permission`，不要直接读取 `sessionStorage.permissions`。
- 语言切换走 `useAppStore.setLocale`，不要绕过 `src/locales` 直接写 locale 状态。
- 表单弹窗展示模式走 `useAppStore.formMode`，模块级特殊交互可在调用处覆盖。
