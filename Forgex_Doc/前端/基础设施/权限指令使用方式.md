# 权限指令使用方式

> 版本：`V0.6.5`

`v-permission` 用于控制按钮、操作入口等前端元素是否显示。它只负责前端展示控制，接口访问权限必须由后端 `@RequirePerm` 或网关/服务端权限机制兜底。

## 一、基础用法

```vue
<a-button v-permission="'sys:user:add'" type="primary">
  {{ t('common.add') }}
</a-button>

<a-button v-permission="'sys:user:delete'" danger>
  {{ t('common.delete') }}
</a-button>
```

绑定值为权限编码字符串。当前用户无权限时，元素会被设置为 `display: none`；有权限时恢复元素原始 display。

## 二、权限编码来源

1. 后端菜单/按钮配置维护按钮权限编码。
2. 登录后前端调用路由接口获取 `buttons`。
3. `permissionStore.set权限s` 将按钮权限写入 `sessionStorage.permissions`。
4. 指令通过 `permissionStore.has权限` 判断是否显示元素。

## 三、使用约定

- 按钮权限编码必须与后端接口权限编码保持一致。
- 页面级菜单权限由动态路由控制，按钮级权限使用 `v-permission`。
- 表格行操作、下拉菜单项、批量操作按钮都应按按钮权限控制。
- 对于同一操作，不要在模板中同时写多套权限判断逻辑。

## 四、与后端配合

前端隐藏按钮不能替代后端鉴权。新增接口时：

1. 后端 Controller 或方法按项目权限机制配置权限编码。
2. 菜单按钮配置使用相同编码。
3. 前端按钮使用 `v-permission` 绑定相同编码。
4. 接口返回无权限时仍按统一响应和提示链路处理。

## 五、排查建议

- 按钮不显示：检查 `sessionStorage.permissions` 是否包含对应编码。
- 登录后权限未刷新：清理权限和动态路由缓存后重新登录。
- 前端显示但接口无权限：检查按钮编码和后端接口权限编码是否一致。
- 列表操作中部分按钮异常：确认 `v-permission` 是否绑定在实际渲染的按钮或菜单项上。
