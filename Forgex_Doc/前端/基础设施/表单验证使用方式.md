# 表单验证使用方式

> 版本：`V0.8.5`

Forgex 前端表单基于 Ant Design Vue `a-form`、`rules` 和 `FormInstance` 实现。新增编辑页、弹窗、抽屉和配置表单时，应在提交前完成前端必填、格式和联动校验，再调用后端接口。

## 一、基础写法

```vue
<a-form ref="formRef" :model="formState" :rules="rules" layout="vertical">
  <a-form-item name="name" :label="t('system.user.name')">
    <a-input v-model:value="formState.name" />
  </a-form-item>
</a-form>
```

```ts
import type { FormInstance, Rule } from 'ant-design-vue/es/form'

const formRef = ref<FormInstance>()
const rules: Record<string, Rule[]> = {
  name: [{ required: true, message: t('common.validation.required'), trigger: 'blur' }]
}

async function handleSubmit() {
  await formRef.value?.validate()
  // 校验通过后再提交接口
}
```

## 二、规则组织

- 静态规则可使用普通对象。
- 需要读取 i18n、状态或 props 的规则使用 `computed`。
- 多步骤或多表单页面可以拆成 `basicRules`、`detailRules`。
- 仅校验部分字段时使用 `validateFields(['fieldA', 'fieldB'])`。

## 三、i18n 文案

校验提示文案应使用 `t(...)`，不新增硬编码中文。历史页面可逐步迁移，新增页面必须直接使用五语言 locale key。

## 四、提交约定

1. 点击保存或下一步时先执行 `validate`。
2. 前端校验通过后再组装接口参数。
3. 接口错误交给 HTTP 统一拦截和业务提示处理。
4. 弹窗关闭或重置时调用 `clearValidate`，避免旧错误残留。

## 五、常见场景

| 场景 | 建议 |
|---|---|
| 必填 | `required: true`，明确 trigger |
| 长度 | 使用 `min`、`max` 或自定义 validator |
| 编码/账号 | 使用正则或自定义 validator，并保持后端二次校验 |
| 远程校验 | 前端只做辅助提示，最终以后端返回为准 |
| 动态表单 | 规则随字段配置生成，提交前统一 validate |
