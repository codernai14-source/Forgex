# 路由与菜单使用方式

> 版本：`V0.8.5`

Forgex 前端采用静态基础路由 + 后端动态菜单路由的模式。新增页面时，需要同时确认后端菜单配置、前端组件路径和按钮权限编码。

## 一、新增菜单页面流程

1. 在 `src/views` 下按模块创建页面，例如系统模块使用 `src/views/system/...`。
2. 在后端菜单或初始化 SQL 中配置模块、菜单路径、组件 key、标题 i18n key、按钮权限。
3. 确认模块编码能被 `src/router/index.ts` 的 `modulePathMap` 映射到前端目录。
4. 组件 key 优先使用稳定映射；普通页面可按 `ModulePage` 约定自动解析。
5. 登录后由路由守卫拉取后端 routes/modules 并注入到 `Workspace` 子路由。

## 二、路径约定

| 类型 | 约定 |
|---|---|
| 登录页 | `/login` |
| 注册页 | `/register` |
| 初始化向导 | `/init` |
| 工作区根路径 | `/workspace`，默认重定向到 `/workspace/home` |
| 动态菜单 | `/workspace/{moduleCode}/{menuPath}` |
| 隐藏详情页 | 在本地 `localModuleRoutes` 或后端菜单中配置 `meta.hidden = true` |

## 三、组件 key 建议

- 系统模块优先使用 `SystemUser`、`SystemRole`、`SystemDashboard` 这类 PascalCase key。
- 基础资料模块使用 `BasicMaterial`、`BasicSupplier` 等 key。
- 审批模块使用已有 `ApprovalTaskConfig`、`ApprovalMyPending` 等稳定 key。
- 特殊页面应补充到 `stableComponentMap` 或模块专属映射，避免依赖模糊匹配。

## 四、菜单展示要求

- 菜单标题使用 i18n key，不直接写中文标题。
- catalog 类型菜单只作为目录展示，不注册最终页面路由。
- 按钮节点不注册页面路由，只用于按钮权限。
- 菜单图标应使用已有图标选择器可选值，保持后端配置与前端渲染一致。

## 五、排查建议

- 菜单不出现：先查后端 routes/modules 返回，再查 `permissionStore` 缓存版本。
- 页面空白：检查 component key 是否能映射到 `src/views` 下实际文件。
- 刷新后丢菜单：检查 localStorage 动态路由缓存和 `ROUTE_CACHE_VERSION`。
- 登录后跳回登录页：检查 `sessionStorage.account` 和 `sessionStorage.tenantId` 是否存在。

## 目录默认跳转
- 侧边菜单点击带子级的目录时，会递归查找目录下第一个可导航页面并跳转。
- 可导航页面要求存在 `path`，且类型不是 `catalog`、`module` 或 `button`。
- 目录下第一项仍是目录时，会继续向下查找第一个页面。
