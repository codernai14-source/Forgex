# 个人首页与可拖拽布局实现逻辑

> 分类：前端 / 国际化与布局
> 版本：**V0.6.5**
> 更新时间：**2026-04-17**

本文档说明个人首页设计器的实现逻辑，包括首页布局配置、组件拖拽、当前用户配置与租户/公共配置的关系，以及代码具体位置。

## 功能定位

Forgex 的个人首页不是写死的一张首页，而是一套“可配置的首页布局系统”。

它主要解决以下问题：

- 首页卡片可以拖拽排序
- 小组件可以显示或隐藏
- 当前用户可以保存自己的首页布局
- 管理端可以维护租户级、公共级默认布局
- 首页组件目录支持公共、租户、个人三级来源
- 首页数据和布局配置分离

核心组件是：

```text
PersonalHomepageDesigner.vue
```

## 布局配置模型

布局配置类型定义在：

```text
Forgex_MOM/Forgex_Fronted/src/api/system/personalHomepage.ts
```

主要结构分为两层：

### layout

描述网格整体规则，例如：

- 列数
- 行高
- 横向纵向间距
- 平板和移动端列数

### widgets

描述每个卡片，例如：

- `key`
- `visible`
- `x/y`
- `w/h`
- `minW/minH`
- `orderNum`
- `params`

这意味着首页的“形”和“内容”是分开的：

- `layout` 决定怎么摆
- `widgets` 决定摆什么、显示什么

## 默认配置逻辑

默认配置在 `createDefaultPersonalHomepageConfig()` 中生成。

系统内置了以下小组件：

- `commonMenus`
- `myFavorites`
- `pendingApprovals`
- `calendar`
- `messages`
- `notices`
- `currentTime`

这套默认配置是首页的兜底方案。
即使后端没有返回配置，前端也能先渲染出一张完整首页。

## 首页组件目录

首页的可选组件不再只靠前端硬编码，而是增加了数据库维护的组件目录，前端只负责承载已注册组件，不做运行时任意路径加载。

### 后端接口

组件目录接口统一走：

```text
/sys/homepage/component/*
```

主要能力包括：

- 组件分页查询
- 组件新增、编辑、删除
- 拉取公共配置到租户
- 当前用户拉取租户配置
- 个人收藏、添加、移除首页组件

### 层级规则

组件目录按三层来源生效：

1. 个人偏好快照
2. 租户组件配置
3. 公共组件配置

其中“删除组件”不是删除公共库，而是删除当前用户自己的偏好快照或移除状态。

### 图标处理

图标字段兼容两类写法：

- 现有 Ant Design 图标名
- Iconify 名称，例如 `lucide:layout-dashboard`

前端通过 `FxIcon` 统一渲染，内部优先尝试 Ant Design 图标，再兼容 Iconify 名称。

## 配置获取与保存链路

前端区分两套模式：

### current 模式

给当前登录用户使用。
对应接口：

- `getCurrentPersonalHomepageConfig()`
- `saveCurrentPersonalHomepageConfig()`
- `resetCurrentPersonalHomepageConfig()`

### manage 模式

给后台管理默认布局使用。
对应接口：

- `getManagePersonalHomepageConfig(scopeLevel)`
- `saveManagePersonalHomepageConfig(scopeLevel, config)`

这里的 `scopeLevel` 用来区分：

- `TENANT`
- `PUBLIC`

## 模块首页配置维度

模块首页在个人首页配置能力上增加 `moduleCode` 维度，接口仍复用 `personalHomepage.ts` 中的当前配置、管理配置、保存和重置方法。

配置 key 约定：

| 场景 | key |
|---|---|
| 个人首页当前用户配置 | `personal.homepage` |
| 个人首页默认配置 | `personal.homepage.default` |
| 模块首页当前用户配置 | `module.homepage.{moduleCode}` |
| 模块首页默认配置 | `module.homepage.default.{moduleCode}` |

公共级默认配置直接使用上表默认配置 key；租户级默认配置因 `sys_config.config_key` 为唯一键，会追加租户后缀，实际 key 为 `{默认配置 key}.tenant.{tenantId}`，读取时兼容旧的未带租户后缀 key。

前端会把历史或路由中出现的模块别名归一化，例如 `system` 归一为 `sys`，`workflow` 归一为 `approval`。

模块首页默认 widget：

| moduleCode | 默认 widget |
|---|---|
| `basic` | `supplierInfo`、`encodeRuleInfo` |
| `approval` | `approvalWeeklyTrend`、`approvalShortcuts`、`approvalUserShare`、`approvalTaskConfig`、`approvalPending`、`approvalProcessed`、`approvalCc` |
| `sys` | `systemStats`、`systemCpu`、`systemMemory`、`systemJvmMemory`、`systemMap`、`systemServerInfo`、`systemOperationLogs`、`systemLoginLogs` |

系统配置页的“个人首页”页签左侧通过模块卡片切换配置对象；个人首页继续使用 `PersonalHomepageDesigner`，基础信息、审批管理、系统管理使用 `ModuleHomepageDesigner`，公共级和租户级配置都落在系统配置体系内。

系统管理和审批管理首页保留真实业务图表能力，图表卡片通过 `ModuleHomepageDesigner` 的命名插槽渲染，插槽名称与 widget key 一一对应。这样页面展示的是原有系统统计、CPU、内存、地图、日志以及审批周趋势、发起人占比等业务卡片，同时这些卡片仍然参与同一套网格拖拽、缩放、显隐和保存流程。

`ModuleHomepageDesigner` 对业务图表页提供两项配套能力：

- `hiddenWidgetKeys`：过滤历史兼容 widget 或当前权限不可用 widget，过滤后的卡片不会出现在网格和配置面板中。
- `layoutUpdated`：在配置加载、拖拽缩放、显隐变化、切换编辑态后发出，业务页用它在 DOM 稳定后初始化或 resize ECharts，避免图表容器异步出现时渲染为空。

模块首页展示文案统一维护在 `src/locales/{lang}/personalHomepage.ts` 的 `module` 分组中，包含模块名称、模块首页标题、配置提示、默认 widget 文案和统计字段文案。审批首页的业务图表、快捷发起、更多入口等审批专属文案继续维护在 `src/locales/{lang}/workflow.ts` 的 `dashboard` 分组中。新增或调整模块首页 widget 时，需要同步覆盖 `zh-CN`、`zh-TW`、`en-US`、`ko-KR`、`ja-JP` 五套语言，避免非默认语言回退为英文或简体中文。

## 配置合并逻辑

前端拿到后端配置后，会先经过：

```ts
mergePersonalHomepageConfig(config)
```

它做的事情包括：

- 用默认布局补齐缺失字段
- 将后端已有 widget 合并到默认 widget
- 保证内置卡片始终存在
- 对某些卡片参数做强制修正

例如：

- 常用菜单固定 Top 6
- 我的收藏固定保留“更多”入口

这说明首页不是完全自由拖拽，而是在“可配置范围内可拖拽”。

## 网格拖拽实现

真正的拖拽布局由：

```text
vue-grid-layout-v3
```

实现。

`PersonalHomepageDesigner.vue` 中通过：

- `GridLayout`
- `GridItem`

渲染每个 widget。

工作流程如下：

1. 前端根据 `config.widgets` 生成 `gridLayout`
2. 用户拖拽或缩放卡片
3. `gridLayout` 变化后反向同步回 `config.widgets`
4. 点击保存时提交整个配置

因此页面上拖的是显示层，真正保存的是配置层。

## 数据与布局分离逻辑

个人首页有两类数据：

### 布局数据

比如卡片位置、显隐、宽高、限制条数。
这类数据保存到个人首页配置接口。

### 业务数据

比如：

- 常用菜单
- 收藏菜单
- 待审批
- 未读消息

这类数据来自各自业务接口，例如：

- `getUserCommonMenus`
- `getUserFavoriteMenus`
- `pageMyPending`
- `listUnreadMessages`

这样设计的好处是：首页布局不依赖具体业务数据结构变化。

## 当前首页与收藏管理页的关系

`src/views/home/index.vue` 本身非常轻，只负责挂载：

```vue
<PersonalHomepageDesigner mode="current" />
```

收藏管理页则是个人首页体系的一个配套页面，用于：

- 查看全部收藏菜单
- 调整收藏顺序
- 批量取消收藏

也就是说，个人首页设计器负责“首页显示”，收藏管理页负责“收藏治理”。

## 系统通知弹窗接入

个人首页入口还挂载了 `SystemNoticePopup`。组件位于 `src/components/system/SystemNoticePopup.vue`，由 `MainLayout.vue` 统一加载，只在路由进入 `/workspace/home` 时调用 `/sys/notice/popup/list` 获取当前用户未确认的有效通知。

弹窗展示系统通知的富文本 HTML、公共/租户范围标识和附件列表。用户点击“我知道了”或关闭弹窗后，组件调用 `/sys/notice/popup/ack` 写入用户级确认记录；同一用户、同一租户、同一通知只弹一次。管理页面位于 `src/views/system/notice/index.vue`，使用 `FxDynamicTable` 的后端表格配置 `SystemNoticeTable`，富文本编辑器使用 `@wangeditor/editor-for-vue`，图片和附件统一复用 `/sys/file/upload`，`moduleCode` 为 `sys_notice`。

## 为什么这样设计

### 1. 首页个性化与平台治理都能兼顾

用户可以改自己的首页，管理员也能提供默认首页。

### 2. 页面扩展性更强

新增一个 widget，不需要重写整张首页，只要补默认配置和渲染逻辑。

### 3. 布局持久化简单

前端只需要保存 JSON 配置，不需要存一堆分散字段。

## 常见排查

### 首页卡片拖了但刷新后恢复原样

优先检查：

1. 是否点击了保存
2. 保存接口是否成功
3. 当前模式是 `current` 还是 `manage`

### 某个 widget 不显示

优先检查：

1. `config.widgets` 中该项是否 `visible=false`
2. 该 widget 的业务数据是否加载失败

### 收藏菜单数量不对

优先检查：

1. 当前逻辑是否被固定为 Top 6
2. 是否在收藏管理页重新保存过排序

### 管理模式下保存了但普通用户首页没变化

优先检查：

1. 当前用户是否已有自己的 `current` 配置
2. 租户级或公共级配置是否只是默认值，没有覆盖用户级配置

## 本次补充说明

### 首页菜单与模块名称多语言统一解析

个人首页、收藏管理页、主布局菜单、全局搜索等菜单展示链路，统一复用 `src/utils/menuI18n.ts`。

统一解析顺序如下：

1. 优先把后端返回值当作 i18n key 处理。
2. 如果后端返回的是多语言 JSON，则按当前语言解析。
3. 如果接口仍返回旧中文标题，则走历史中文翻译兜底。
4. 如果只有菜单路径或模块编码，则回退到路由标题、动态路由标题或 `{moduleCode}.title` 对应语言包文案。

这样可以保证首页卡片、收藏页、主菜单、搜索结果等场景尽量显示一致的当前语言标题，减少中文残留和 key 直出的情况。

### 语言切换后的刷新策略

首页类页面中的部分菜单、收藏、模块数据依赖接口返回，单纯切换前端语言状态不足以让已加载数据自动切换文案。因此语言切换成功后，主布局会执行整页刷新，重新拉取首页、菜单、收藏等接口数据。

这项策略用于保证 `en-US / zh-TW / ja-JP / ko-KR` 切换后，个人首页常用菜单、我的收藏、系统管理首页、审批首页等依赖接口的数据型标题跟随当前语言重新渲染。
