## 未完成能力和下一步

Android 工程中仍存在 19 个 `*PlaceholderScreen.kt`，集中在 `feature/basic`、`equipment`、`integration`、`label`、`production`、`quality`、`report`、`warehouse` 及注册页。这些模块当前完成模块边界、导航和占位 UI，未完成真实 API、Repository、ViewModel、业务表单/列表和测试。下一步顺序应为：补 `core/network` API 契约，补 Repository 与 ViewModel，接入真实 Compose 页面，再增加离线/错误态测试。

`安卓端/离线能力.md` 明确记录 Room 数据库和 WorkManager 同步目前只有规划，不能对外宣称已支持离线写入。

`数据库/安全与配置/TDE透明加密使用方式.md` 明确记录仓库没有 Forgex 管理的 MySQL 原生 TDE 开关；TDE 只能由 DBA 按目标数据库能力评估，应用层字段加密另见加密专题。

## 维护规则

1. 以源码路径、公开类名、接口映射和测试为依据更新文档；源码没有实现时写明“骨架/规划/未完成”和下一步。
2. 每份使用方式文档至少保留一个来自当前源码的 Java、Kotlin、TypeScript 或 SQL 示例。
3. API 路径必须从 Controller 或前端 API 文件核对，不能凭 REST 惯例编写。
4. 新版本发布时同步更新本报告的核对日期、自动检查数字和受影响专题。
