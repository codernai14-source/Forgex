# 网络层与统一结果

> 分类：安卓端 / 专题
> 版本：V0.8.0
> 关联模块：`core/network`

本文说明 Forgex Android 端网络层的封装方式、OkHttp 拦截器链、与后端统一响应体 `R<T>` 的对齐策略，以及统一错误处理规范。

---

## 一、整体结构

`core/network` 模块负责所有 HTTP 通信，对外暴露 `ApiService` 接口，对内基于 Retrofit + OkHttp 封装。feature 模块不直接持有 Retrofit，而是通过 Hilt 注入对应的 Repository，Repository 再调用 `ApiService`。

```
feature/* (Repository)
      │ 依赖注入
      ▼
core/network
      ├── ApiService（Retrofit 接口定义）
      ├── NetworkModule（Hilt 提供 Retrofit / OkHttp）
      ├── interceptor/（拦截器链）
      ├── model/（R<T>、错误码、分页模型）
      └── handler/（统一错误处理）
```

## 二、Retrofit 封装

`NetworkModule` 通过 Hilt `@Module` 提供 `Retrofit` 与 `OkHttpClient` 单例：

- `BASE_URL` 由 `BuildConfig` 注入，按 `dev / test / prod` 区分网关地址。
- Retrofit 配置 `GsonConverterFactory`（或 Moshi），统一序列化策略。
- 超时：连接 15s、读取 30s、写入 30s，可通过构建参数覆盖。
- 启用 `HttpLoggingInterceptor`，`debug` 构建类型打印 BODY，`release` 仅打印 BASIC。

```kotlin
@Module
@InstallIn(SingletonComponent::class)
object NetworkModule {

    @Provides
    @Singleton
    fun provideOkHttpClient(
        authInterceptor: AuthInterceptor,
        tenantInterceptor: TenantInterceptor,
    ): OkHttpClient = OkHttpClient.Builder()
        .connectTimeout(15, TimeUnit.SECONDS)
        .readTimeout(30, TimeUnit.SECONDS)
        .writeTimeout(30, TimeUnit.SECONDS)
        .addInterceptor(authInterceptor)
        .addInterceptor(tenantInterceptor)
        .apply {
            if (BuildConfig.DEBUG) {
                addInterceptor(HttpLoggingInterceptor().apply {
                    level = HttpLoggingInterceptor.Level.BODY
                })
            }
        }
        .build()

    @Provides
    @Singleton
    fun provideRetrofit(client: OkHttpClient): Retrofit =
        Retrofit.Builder()
            .baseUrl(BuildConfig.BASE_URL)
            .client(client)
            .addConverterFactory(GsonConverterFactory.create())
            .build()
}
```

## 三、OkHttp 拦截器链

拦截器按以下顺序执行，职责单一，禁止在拦截器中做业务逻辑：

| 顺序 | 拦截器 | 职责 |
|---|---|---|
| 1 | `AuthInterceptor` | 从 DataStore 读取 Token，注入 `Authorization: Bearer <token>` 请求头；未登录则跳过 |
| 2 | `TenantInterceptor` | 从 DataStore 读取当前租户编码，注入 `X-Tenant-Code` 请求头 |
| 3 | `HttpLoggingInterceptor` | 调试日志（仅 DEBUG 构建） |

### 3.1 AuthInterceptor 要点

- Token 从 `core/datastore` 的 `SessionDataStore` 异步读取，拦截器内使用 `runBlocking` 阻塞获取（仅在请求线程，开销可控）。
- 401 响应由全局错误处理统一处理，触发刷新 Token 或跳转登录页，拦截器本身不处理 401。
- 登录、验证码等免登接口通过 `@Headers("No-Auth: true")` 注解标记，`AuthInterceptor` 识别后跳过注入。

## 四、与后端 R<T> 模型对齐

后端统一响应体结构如下，Android 端在 `core/network/model` 中定义对应 Kotlin 数据类：

### 4.1 后端结构

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { ... }
}
```

### 4.2 Android 对齐模型

```kotlin
/**
 * 后端统一响应体，与 com.forgex.common.web.R 对齐。
 */
data class ApiResponse<T>(
    val code: Int,
    val message: String?,
    val data: T?,
) {
    /** 业务是否成功（code == 200） */
    val isSuccess: Boolean get() = code == SUCCESS_CODE

    companion object {
        const val SUCCESS_CODE = 200
    }
}
```

### 4.3 挂起函数返回值约定

- **成功**：Retrofit 接口返回 `ApiResponse<T>`，Repository 层校验 `isSuccess`，成功则解包返回 `T`。
- **失败**：`code != 200` 时，Repository 抛出 `ApiException(code, message)`，由 ViewModel 统一捕获。

```kotlin
interface AuthApi {
    @Headers("No-Auth: true")
    @POST("api/auth/login")
    suspend fun login(@Body req: LoginRequest): ApiResponse<LoginResult>
}
```

Repository 解包示例：

```kotlin
class AuthRepository @Inject constructor(
    private val api: AuthApi,
) {
    suspend fun login(req: LoginRequest): LoginResult {
        val resp = api.login(req)
        if (!resp.isSuccess) {
            throw ApiException(resp.code, resp.message.orEmpty())
        }
        return resp.data ?: throw ApiException(-1, "响应数据为空")
    }
}
```

## 五、统一错误处理

### 5.1 错误分类

| 类型 | 触发场景 | 处理方式 |
|---|---|---|
| `ApiException` | 后端返回业务错误（code != 200） | 直接展示 `message` |
| `IOException` | 网络不可达、超时、DNS 失败 | 展示「网络连接失败，请检查网络」 |
| `HttpException` | HTTP 状态码非 2xx（ Retrofit 抛出） | 按 status 映射提示语 |
| 401 | Token 过期/无效 | 清除会话，跳转登录页 |
| 其他 `Throwable` | 未知异常 | 展示「未知错误」，记录日志 |

### 5.2 全局处理入口

ViewModel 中通过 `try-catch` 或 `Result` 包装捕获异常，映射为 UI 状态：

```kotlin
sealed interface UiState<out T> {
    data object Loading : UiState<Nothing>
    data class Success<T>(val data: T) : UiState<T>
    data class Error(val message: String) : UiState<Nothing>
}
```

- `ApiException` 与 `IOException` 在 Repository 层即转换为可读消息。
- 401 错误通过全局 `AuthEventBus`（SharedFlow）通知，由 `app` 层监听并统一跳转登录，避免每个页面重复处理。

## 六、规范约定

1. **禁止在 feature 层直接使用 OkHttpClient / Retrofit**，必须通过 Repository 间接调用。
2. **统一使用 `ApiResponse<T>` 包装**，不要在 Retrofit 接口中直接返回裸 `T`。
3. **错误消息面向用户**，技术细节写入日志，不直接展示给用户。
4. **拦截器保持无状态**，Token / Tenant 来源仅限 DataStore，禁止在拦截器内缓存可变状态。
5. **超时与重试**：默认不自动重试非幂等请求，幂等请求（GET）可由 OkHttp `RetryAndFollowUpInterceptor` 默认行为处理。
