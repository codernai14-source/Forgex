# 网络层与统一结果

> 分类：安卓端 / 网络
> 版本：V1.0.0
> 关联模块：`core/network`、`core/common`、`core/datastore`

本文只说明 Android 网络请求和统一结果处理。内容以当前源码为准；未实现的刷新令牌、全局跳转等能力不会作为已完成能力描述。

## 1. 网络模块组成

`core/network` 通过 Retrofit 定义接口，通过 Hilt 提供 `Retrofit`、`OkHttpClient` 和各 API 实例。默认地址由 `app` 模块的 `BuildConfig.BASE_URL` 提供，当前构建配置使用 `/api/` 作为路径前缀。`DynamicBaseUrlInterceptor` 可以在请求前根据 `SessionStore.serverEndpoint` 改写 scheme、host 和 port，路径与查询参数保持不变。

当前已注册的 API 包括 `AuthApi`、`I18nApi`、`MenuApi`、`WorkflowApi`、`MessageApi` 和 `WorkbenchApi`。

## 2. Retrofit 接口示例

认证接口的实际路径位于 `AuthApi.kt`，不包含旧文档中的 `api/` 前缀：

```kotlin
interface AuthApi {
    @GET("auth/crypto/public-key")
    suspend fun getPublicKey(): ApiResponse<String>

    @POST("auth/login")
    suspend fun login(@Body request: LoginRequest): ApiResponse<LoginResult>

    @POST("auth/chooseTenant")
    suspend fun chooseTenant(@Body request: TenantChoiceRequest): ApiResponse<SysUserDTO>

    @POST("auth/logout")
    suspend fun logout(): ApiResponse<Boolean>
}
```

验证码和系统配置也由同一个接口声明，具体路径以 `AuthApi.kt` 中的注解为准。

## 3. OkHttp 配置和拦截器顺序

`NetworkModule.provideOkHttpClient` 的实际顺序如下。Cookie Jar 不是 interceptor，但会在请求前后参与 Cookie 读写。

| 顺序 | 组件 | 当前行为 |
| --- | --- | --- |
| Cookie | `SessionCookieJar` | 按 host 保存和读取未过期 Cookie，内存级别保存 |
| 1 | `DynamicBaseUrlInterceptor` | 使用 `serverEndpoint` 改写目标地址 |
| 2 | `AuthInterceptor` | 从 `SessionStore.token` 读取 Token，添加 `Authorization: Bearer <token>` |
| 3 | `TenantInterceptor` | 从 `SessionStore.tenantId` 读取租户，添加 `X-Tenant-Id` |
| 4 | `LanguageInterceptor` | 添加 `X-Lang` 和 `Accept-Language` |
| 5 | `HttpLoggingInterceptor` | 当前源码固定为 `BODY` 级别 |

示例配置来自 `NetworkModule.kt`：

```kotlin
return OkHttpClient.Builder()
    .cookieJar(sessionCookieJar)
    .addInterceptor(dynamicBaseUrlInterceptor)
    .addInterceptor(authInterceptor)
    .addInterceptor(tenantInterceptor)
    .addInterceptor(languageInterceptor)
    .addInterceptor(loggingInterceptor)
    .build()
```

拦截器使用 `runBlocking` 读取 DataStore Flow，这是当前实现方式；调用方不应在 feature 中重复添加这些请求头。

### 3.1 租户头协议

Android `TenantInterceptor` 使用 `X-Tenant-Id`。网关从登录会话派生最终的用户和租户头并向下游透传，因此客户端请求头只用于三端契约对齐，不构成网关的租户信任来源。

## 4. 统一响应模型

`core/common/model/ApiResponse.kt` 是 Retrofit 的统一响应体：

```kotlin
data class ApiResponse<T>(
    val code: Int? = null,
    val message: String? = null,
    val msg: String? = null,
    val data: T? = null,
    val messageCode: String? = null,
    val i18n: ApiResponseI18nMeta? = null
) {
    fun isSuccess(): Boolean = code == 200

    fun errorMessage(): String = message ?: msg ?: "Unknown error"
}
```

成功条件是 `code == 200`。错误信息优先使用 `message`，其次使用 `msg`，都为空时使用 `Unknown error`。`messageCode` 和 `i18n` 用于保留后端国际化元数据。

## 5. ApiExecutor 与 AppResult

`ApiExecutor.request` 接收返回 `ApiResponse<T>` 的挂起函数，成功时转换为 `AppResult.Success`，业务错误通过 `ErrorCodeMapper` 转换为 `AppResult.Error`，异常也由同一映射器处理。当前存在带 mapper 的重载，可把 `T?` 转换为其他结果类型。

```kotlin
private val apiExecutor = ApiExecutor()

suspend fun login(api: AuthApi, request: LoginRequest): AppResult<LoginResult> =
    apiExecutor.request { api.login(request) }
```

结果类型来自 `AppResult.kt`：

```kotlin
sealed interface AppResult<out T> {
    data class Success<T>(val data: T) : AppResult<T>
    data class Error(
        val message: String,
        val code: Int? = null,
        val appText: AppText? = null
    ) : AppResult<Nothing>
    data object Loading : AppResult<Nothing>
}
```

`ErrorCodeMapper` 对 `401`、`601`、`602`、`603`、`604`、`605`、`606`、`9001` 提供专门文案，其中 `603` 提示服务稍后重试，`606` 提示先修改密码。映射同时附带 `AppText.Dynamic`，可由在线语言包覆盖默认文案；超时和 `IOException` 分别返回请求超时、网络连接异常。源码没有实现自动刷新 Token 或请求重放。

## 6. Repository 调用约定

feature 模块应注入已注册的 API 和 `ApiExecutor`，把 `ApiResponse` 转换为 `AppResult` 后交给 ViewModel。不要在页面中直接解析 `code`，也不要自行创建另一套异常模型。

```kotlin
class LoginRepository @Inject constructor(
    private val authApi: AuthApi,
    private val apiExecutor: ApiExecutor,
) {
    suspend fun login(request: LoginRequest): AppResult<LoginResult> =
        apiExecutor.request { authApi.login(request) }
}
```

当前源码未发现文档旧版本所称的 `SessionDataStore`、`AuthRepository`、`ApiException`、`AuthEventBus` 或自动刷新 Token 实现。需要这些能力时，应新增明确的 Repository、会话失效事件和测试，并同步更新本页。

## 7. 使用限制

1. 所有网络接口返回 `ApiResponse<T>`，统一通过 `ApiExecutor` 转换结果。
2. Token、租户和语言头由拦截器统一添加。
3. 日志拦截器当前为 `BODY` 级别，生产环境发布前应评估敏感数据脱敏和日志级别。
4. 租户头统一使用 `X-Tenant-Id`；业务租户上下文仍以网关会话派生结果为准。
