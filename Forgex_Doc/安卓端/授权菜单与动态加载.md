# 授权菜单与动态加载

> 分类：安卓端 / 菜单
> 版本：V1.0.0
> 更新时间：2026-09-19
> 关联模块：`core/network`、`core/datastore`、`feature/auth`、`feature/home`

本文说明 PDA/手机端"选租户后一次拉取全部授权模块与菜单"的聚合包机制，以及菜单动态化的边界。内容以当前源码为准。

## 1. 链路总览

1. `POST /api/auth/login` — 登录，返回租户列表与交互码
2. `POST /api/auth/chooseTenant` — 选定租户，建立会话
3. `POST /api/sys/app/c-menu/bundle` — **一次拉取 C 端菜单聚合包**（授权模块整树 + 收藏）

选租户成功后 `AuthViewModel.confirmTenantSelection` 即调用 `AuthRepository.preloadCMenuBundle` 预载聚合包并写入 DataStore 缓存；进入主界面后工作台/收藏页读缓存渲染，零额外网络请求。旧的 `/sys/menu/routes`（B 端接口）已不再在该链路中调用。

## 2. 聚合包接口

- 请求：`POST sys/app/c-menu/bundle`，body `{"deviceType": "MOBILE"}`
- `deviceType` 取值 `MOBILE`（手机/PDA，默认）/ `TABLET`（Pad），后端按 `sys_c_menu.device_type IN (入参, 'ALL')` 过滤，非法或空值按 `MOBILE` 处理
- 响应 `data`：

```json
{
  "modules": [
    {
      "id": 101, "parentId": 0, "name": "工作台", "path": "workbench",
      "icon": "home", "componentKey": "WorkbenchScreen", "type": "catalog",
      "menuMode": "embedded", "deviceType": "ALL",
      "children": [ { "...": "菜单节点，结构与模块相同，可递归" } ]
    }
  ],
  "favorites": [ { "...": "收藏的菜单节点" } ]
}
```

- 授权链路在后端完成：用户 → 角色（`sys_user_role`）→ C 端菜单授权（`sys_role_c_menu`）→ 菜单（`sys_c_menu`，全局行 `tenant_id IS NULL` 与租户行叠加），App 端不做本地过滤
- 旧的两级接口 `workbench/modules`、`workbench/menus` 与 `favorites/*` 保留，作为聚合包失败时的兜底（注意路径需带 `sys/` 前缀经网关路由）

## 3. 客户端缓存

- `SessionStore` 新增键：`c_menu_bundle_json`（聚合包 JSON）、`c_menu_bundle_tenant_id`（归属租户）
- `CMenuBundleRepository`（`core/network/workbench`）负责拉取+缓存+读取，读取时校验租户一致，跨租户缓存直接失效
- `clearSession()` 登出时同步清空缓存
- 注意：当前登录态靠内存 Cookie 维持，进程重启需重新登录（选租户会重新预载），因此缓存生命周期实际等于会话生命周期

## 4. 页面行为

| 页面 | 行为 |
| --- | --- |
| 工作台（`WorkbenchViewModel`） | init 读缓存命中直接渲染；未命中拉聚合包；聚合包失败回退旧 `workbench/modules` 接口；`refresh()` 强制重拉 |
| 模块菜单切换（`selectModule`） | 优先取聚合包内模块 `children` 本地切换（零网络）；无 children 时回退 `workbench/menus` |
| 收藏（`FavoritesViewModel`） | 优先读聚合包缓存中的 `favorites`；未命中走 `favorites/list`；收藏切换后按原接口刷新 |
| 重试按钮 | 调用 `refresh()` 强制刷新聚合包 |

## 5. 菜单动态化边界（重要）

菜单"内容"完全由后端 `sys_c_menu` 配置驱动，但菜单点击后的落点分三档：

| 菜单配置 | 是否需要改 App 代码 | 说明 |
| --- | --- | --- |
| componentKey 命中 `MenuTargetResolver` 现有映射（18 条） | **否** | 管理端 C 菜单管理里配置即生效 |
| `menuMode=external`（H5 外链） | **否** | WebView 容器打开 `externalUrl` |
| 新原生页面 | **是** | 需开发 Compose 页面并在 `MenuTargetResolver.componentKeyRouteMap` 增加一条映射后发版 |

原因：Android 原生页面是编译期产物，无法像 Web 端 `import.meta.glob` 那样在运行时枚举组件池。若未来要求新增原生页面也免改中心映射表，可演进为 Hilt `@IntoSet` 组件池自注册（feature 模块内声明 Entry，自动聚合），属于后续扩展项。

## 6. 管理端配置要点（C 菜单）

- 菜单管理：`系统管理 → C 端菜单`（`SysCMenuController` CRUD + `SysRoleCMenuController` 角色授权）
- 关键字段：
  - `componentKey`：原生页面映射标识（如 `WorkbenchScreen`、`WarehouseScreen`），需与 App 端映射表一致
  - `deviceType`：`MOBILE` / `TABLET` / `ALL`（通用）
  - `menuMode`：`embedded` 内嵌 / `external` 外联；外链必填 `externalUrl`
  - `tenant_id`：`NULL` 表示全局公共菜单，所有租户可见；填租户 ID 则仅该租户可见
- 角色授权后菜单即时对应用生效（App 端下拉刷新/重进工作台后可见）

## 7. 使用限制

1. 聚合包按 `deviceType` 过滤，新增 Pad 专属菜单请配 `TABLET`，不要配 `MOBILE`
2. 收藏切换仍走 `favorites/toggle` 单接口，聚合包不会因收藏变更自动失效
3. 按钮级权限（`permKey`）暂未纳入聚合包，C 端 permKey 也未进 Sa-Token 权限集，属后续扩展
