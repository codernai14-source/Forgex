# 导航与模块规范

> 分类：安卓端 / 专题
> 版本：V0.8.5
> 关联模块：`core/navigation`、`app`、`feature/*`

本文说明 Forgex Android 端的 Navigation Compose 导航方案、feature 模块边界约定与路由表管理规范。

---

## 一、导航方案选型

采用 Jetpack Navigation Compose（`androidx.navigation:navigation-compose`）作为单 Activity 多 Compose 目的地的导航框架：

- **单 Activity 架构**：`MainActivity` 承载唯一 NavHost，所有页面为 Composable destination。
- **类型安全路由**：路由常量集中在 `core/navigation` 的 `Routes` 对象，禁止散落在 feature 内拼接字符串。
- **嵌套导航图**：按 feature 维度划分 NavGraph，feature 暴露 `XxxNavGraph()` Composable 供 `app` 聚合。

## 二、路由表约定

### 2.1 路由常量集中管理

`core/navigation` 定义 `Routes` 对象，所有路由路径与参数 Key 在此声明：

```kotlin
object Routes {
    // 认证
    const val LOGIN = "login"
    const val CHOOSE_TENANT = "choose-tenant"

    // 主框架
    const val MAIN = "main"

    // feature 子路由以命名空间前缀，避免冲突
    object Workflow {
        const val TODO_LIST = "workflow/todo"
        const val TODO_DETAIL = "workflow/todo/{taskId}"
        const val TASK_ARG = "taskId"
    }

    object Message {
        const val LIST = "message/list"
        const val DETAIL = "message/{messageId}"
        const val MESSAGE_ARG = "messageId"
    }

    object Profile {
        const val SETTINGS = "profile/settings"
    }
}
```

### 2.2 路由命名规范

| 规则 | 说明 | 示例 |
|---|---|---|
| 命名空间前缀 | feature 名作为路由前缀，避免跨模块冲突 | `workflow/todo` |
| 参数用占位符 | 路径参数用 `{param}` 声明 | `workflow/todo/{taskId}` |
| 参数 Key 常量化 | 参数名定义为常量，避免拼写错误 | `Routes.Workflow.TASK_ARG` |
| 下划线或短横线 | 路径用短横线 `choose-tenant`，参数用驼峰 `taskId` | — |

## 三、feature 模块边界

### 3.1 依赖方向

```
app
 ├── core/navigation（路由表）
 ├── core/* （公共能力）
 └── feature/*（业务功能）

feature/auth  ──► core/network, core/datastore, core/ui, core/navigation
feature/workflow ──► core/network, core/ui, core/navigation
feature/* 之间：禁止互相依赖
```

### 3.2 边界约定

| 项 | 允许 | 禁止 |
|---|---|---|
| feature -> core | 允许 | — |
| feature -> feature | — | **禁止**（跨 feature 通信走导航或事件总线） |
| core -> feature | — | **禁止**（core 不感知业务） |
| app -> feature | 允许（聚合 NavGraph） | — |
| feature -> app | — | **禁止** |

### 3.3 feature 对外暴露的契约

每个 feature 模块对外只暴露三类入口，其余实现细节（ViewModel、Repository、Api）均为 `internal`：

1. **`XxxNavGraph()`**：注册该 feature 的所有 destination，供 `app` 的 NavHost 调用。
2. **`XxxRoute`（可选）**：跨模块跳转辅助函数，封装 `navController.navigate(...)`。
3. **入口数据模型**（可选）：如 `WorkflowTask`，如果被其他 feature 引用则放 `core/model`。

```kotlin
// feature/workflow 对外暴露
fun WorkflowNavGraph(navController: NavHostController) {
    composable(Routes.Workflow.TODO_LIST) { WorkflowTodoScreen(navController) }
    composable(
        route = Routes.Workflow.TODO_DETAIL,
        arguments = listOf(navArgument(Routes.Workflow.TASK_ARG) { type = NavType.StringType }),
    ) { entry ->
        WorkflowTodoDetailScreen(
            taskId = entry.arguments?.getString(Routes.Workflow.TASK_ARG).orEmpty(),
            navController = navController,
        )
    }
}
```

### 3.4 app 层聚合

`app` 模块的 `MainNavHost` 聚合所有 feature 的 NavGraph：

```kotlin
@Composable
fun ForgexNavHost(navController: NavHostController, startDestination: String) {
    NavHost(navController = navController, startDestination = startDestination) {
        AuthNavGraph(navController)
        MainNavGraph(navController)         // 底部 Tab 框架
        WorkflowNavGraph(navController)
        MessageNavGraph(navController)
        ProfileNavGraph(navController)
    }
}
```

## 四、导航操作规范

### 4.1 跳转

- 跨 feature 跳转：调用目标 feature 暴露的 `XxxRoute` 辅助函数，或直接 `navController.navigate(Routes.Xxx)`。
- 传参：用 `navArgument` 声明类型，跳转时通过 `buildRoute` 或 lambda 传参，禁止手动拼接 URL。

```kotlin
fun navigateToTodoDetail(navController: NavHostController, taskId: String) {
    navController.navigate("${Routes.Workflow.TODO_DETAIL}/$taskId")
}
```

### 4.2 返回

- 使用 `navController.popBackStack()`，不要用系统返回键直接 finish Activity。
- 登录成功后用 `popUpTo(Routes.LOGIN) { inclusive = true }` 清除登录栈，防止返回键回到登录页。

### 4.3 深层链接

- 消息点击跳转对应业务详情页，通过 `Routes` 常量构建，禁止硬编码字符串。

## 五、规范约定

1. **路由集中**：所有路由字符串必须在 `Routes` 中声明，feature 内禁止出现裸字符串路由。
2. **feature 隔离**：feature 之间零依赖，跨模块通信只走导航或事件总线。
3. **internal 封装**：feature 的 ViewModel / Repository / Api 一律 `internal`，仅暴露 NavGraph 与必要的入口模型。
4. **导航栈管理**：登录、登出等关键节点必须显式管理 `popUpTo`，避免导航栈残留敏感页面。
5. **新增 feature**：先在 `Routes` 注册路由，再实现 `XxxNavGraph`，最后在 `app` 的 NavHost 聚合，三步缺一不可。
