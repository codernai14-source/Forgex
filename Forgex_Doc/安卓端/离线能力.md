# 离线能力

> 分类：安卓端 / 专题
> 版本：V0.8.0
> 关联模块：`core/database`（规划）、`core/sync`（规划）
> 联动：问题9「移动端无离线能力」

本文说明 Forgex Android 端离线能力的整体架构框架。当前为框架占位说明，详细实现随问题9（离线能力架构设计）落地后补充。

---

## 一、背景与目标

### 1.1 现状

- `libs.versions.toml` 已声明 Room 依赖（room-runtime / room-ktx / room-compiler），但全工程无任何 `@Database` 类——依赖声明了却未使用。
- 无 WorkManager，无同步队列，无离线缓存。
- 网络断开即完全不可用。

### 1.2 目标

- 断网状态下可查看已缓存的历史数据（只读缓存优先）。
- 断网时的写操作进入本地同步队列，联网后自动重放上传。
- 冲突按「服务端权威 + Last-Write-Wins」策略解决。

## 二、整体架构（框架）

```
┌─────────────────────────────────────────────┐
│  feature/*（业务页面）                        │
│    ├─ 在线：Repository 直连 ApiService         │
│    └─ 离线：Repository 读写 LocalDataSource     │
└──────────────────┬──────────────────────────┘
                   │
┌──────────────────▼──────────────────────────┐
│  core/sync（同步层，规划）                     │
│    ├─ SyncQueue（本地操作队列）                │
│    ├─ SyncWorker（WorkManager 周期/触发上传）   │
│    ├─ ConflictResolver（冲突解决，默认 LWW）    │
│    └─ NetworkMonitor（网络状态监听，联网触发）  │
└──────────────────┬──────────────────────────┘
                   │
┌──────────────────▼──────────────────────────┐
│  core/database（本地库，规划）                 │
│    ├─ ForgexDatabase（@Database）             │
│    ├─ BaseEntity / BaseDao（抽象基类）         │
│    ├─ Converters（时间 / JSON 转换）           │
│    └─ Hilt @Provides RoomDatabase             │
└─────────────────────────────────────────────┘
```

## 三、core/database 模块（规划）

### 3.1 职责

- 提供 Room 数据库单例，管理版本与迁移。
- 提供基础 Entity / Dao 抽象，减少 feature 重复代码。
- 提供类型转换器（LocalDateTime、JSON 字段）。

### 3.2 规划结构

```
core/database/
  ├─ ForgexDatabase.kt        // @Database，聚合所有 Entity
  ├─ base/
  │    ├─ BaseEntity.kt        // id / createdAt / updatedAt / synced
  │    └─ BaseDao.kt           // 通用 CRUD 模板
  ├─ converter/
  │    └─ Converters.kt        // LocalDateTime / List<*> 转换
  └─ di/
       └─ DatabaseModule.kt    // Hilt @Provides
```

### 3.3 BaseEntity 字段约定

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | Long | 本地主键 |
| `remoteId` | Long? | 服务端 ID，同步后回填 |
| `createdAt` | LocalDateTime | 本地创建时间 |
| `updatedAt` | LocalDateTime | 本地更新时间 |
| `synced` | Boolean | 是否已同步到服务端 |

## 四、core/sync 模块（规划）

### 4.1 SyncQueue 同步队列

本地操作队列表，记录待上传的写操作：

| 字段 | 说明 |
|---|---|
| `id` | 队列项 ID |
| `entityType` | 操作实体类型（如 `workflow_todo`） |
| `operation` | 操作类型（CREATE / UPDATE / DELETE） |
| `payload` | 操作数据（JSON） |
| `status` | 状态（pending / processing / success / failed） |
| `retryCount` | 重试次数 |
| `createdAt` | 入队时间 |

### 4.2 SyncWorker

- 基于 WorkManager，支持周期性同步与网络恢复触发。
- 约束：`NetworkType.CONNECTED`，仅在联网时执行。
- 流程：取出 pending 项 -> 逐条上传 -> 成功标记 success / 失败重试（指数退避，超过阈值标记 failed）。

### 4.3 冲突解决

- 默认策略：**Last-Write-Wins（LWW）**，以服务端 `updatedAt` 为准。
- 服务端权威：服务端数据覆盖本地，本地仅在被授权字段范围内提交。
- 接口 `ConflictResolver<T>` 可按实体自定义策略。

### 4.4 NetworkMonitor

- 监听 `ConnectivityManager` 网络状态变化。
- 联网恢复时主动触发 `SyncWorker` 的一次性执行（`OneTimeWorkRequest`）。

## 五、首批落地场景（规划）

随问题9实现，首批接入两个场景验证离线链路：

| 场景 | 离线能力 | 优先级 |
|---|---|---|
| `feature/workflow` 待办列表 | 只读缓存优先，断网可查看历史待办 | P0 |
| `feature/message` 消息 | 消息离线缓存 + 离线已读回执入队 | P0 |

其余 feature 后续按需接入，遵循「先只读缓存，后写操作入队」的渐进路径。

## 六、规范约定（待实现后细化）

1. **Repository 双源**：每个接入离线的 feature，Repository 同时持有 `ApiService`（远程）与 `Dao`（本地），按网络状态选择数据源。
2. **缓存优先**：断网或请求失败时返回本地缓存数据，UI 标注「离线数据」。
3. **写操作入队**：断网写操作不直接丢弃，写入 `SyncQueue` 待联网重放。
4. **同步幂等**：服务端接口必须支持幂等，避免重放导致重复数据。
5. **冲突透明**：冲突解决结果通过 Flow 通知 UI，避免静默覆盖用户操作。
