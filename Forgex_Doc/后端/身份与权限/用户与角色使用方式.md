# 用户与角色使用方式

> 分类：后端 / 身份与权限
> 版本：**V0.8.5**
> 更新时间：**2026-08-12**

本文档说明用户、角色相关能力在日常开发和联调中的推荐用法。

## 适用场景

- 新增用户管理接口
- 做角色授权、菜单授权
- 调整默认密码、重置密码逻辑
- 排查用户无菜单、无按钮、无租户权限问题

## 推荐实践

1. 用户新增、编辑、启停都走统一 Service，不要在多个模块重复维护账号状态。
2. 角色授权完成后，注意同步刷新当前登录用户权限或要求重新登录验证。
3. 默认密码、密码重置口径统一受配置控制，不在业务模块中硬编码。
4. 涉及跨租户查用户时，要明确是否忽略租户隔离。
5. **维护直属上级 `superiorUserId`**，供工作流 `ApproverType.SUPERIOR` 解析；跨服务请调 `POST /sys/user/internal/resolveSuperiorUserIds`，不要在业务服务直接递归查库。

## 直属上级与工作流联调

| 项 | 说明 |
|---|---|
| 字段 | `sys_user.superior_user_id` / `superiorUserId` |
| 内部解析接口 | `POST /sys/user/internal/resolveSuperiorUserIds` |
| 请求要点 | `initiatorUserId`、`level`（默认 1） |
| 工作流用法 | 节点审批人类型选「直属上级」，可配 `superiorLevel` |
| Feign 归属 | `Forgex_Sys_Api`（如已封装）或业务侧按契约调用 Sys 内部接口 |

### 已知限制（二开必读）

1. **用户管理前端表单尚未接入** `superiorUserId`（`UserFormDialog` 等无该表单项）；目前主要靠 API / SQL / 管理端直接改库维护。
2. **用户 Excel 导入不读写** `superiorUserId`（见导入导出文档「用户导入专节」），导入无法建立上级链。
3. Auth 侧登录用 `SysUser` 实体若不带该字段，不影响登录；工作流解析走 Sys 内部接口。
4. 部门负责人文本字段（`sys_department.leader`）仍不可作稳定审批人来源。

排查：

| 现象 | 排查点 |
|---|---|
| 上级审批节点无待办人 | 发起人 `superior_user_id` 是否为空、level 是否过大、上级链是否断裂 |
| 解析结果异常为空 | 租户上下文、用户是否删除、上级是否成环 |
| 界面上看不到上级字段 | 属已知缺口；用用户 update API 或 SQL 维护 |

## 新增用户接口示例

```java
@RequirePerm("sys:user:create")
@PostMapping("/create")
public R<Boolean> create(@RequestBody SysUserDTO dto) {
    userService.create(dto);
    return R.ok(CommonPrompt.SAVE_SUCCESS);
}
```

## 角色授权注意点

- 菜单权限与按钮权限需要一起维护。
- 角色删除前要检查是否仍有用户绑定。
- 数据权限范围调整后，要联动验证列表查询结果。

## 常见排查

| 现象 | 排查点 |
|---|---|
| 用户能登录但没有菜单 | `sys_user_role`、`sys_role_menu`、当前租户 |
| 修改角色后前端无变化 | 重新登录、刷新权限缓存 |
| 重置密码后无法登录 | 密码算法、传输加密、公钥配置 |
| 用户查不到所属租户数据 | `sys_user_tenant`、默认租户、TenantContext |
| 上级审批找不到人 | `superior_user_id`、level、工作流节点审批人类型 |

## 第三方联调补充

用户管理页当前已内置第三方联调入口：

- “同步第三方”按钮调用 `sys_user_sync`
- “拉取第三方”按钮调用 `sys_user_pull`

在本地 ERP 联调场景下，这两个接口已约定接入 `127.0.0.1:18080` 的 ERP 测试系统，用于验证 Forgex 接口平台对用户数据的出站同步与回拉同步能力。
