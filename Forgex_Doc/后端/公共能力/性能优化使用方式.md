# 性能优化使用方式

> 版本：**V0.8.5**

性能优化优先从查询边界、分页、索引、缓存和批量处理入手。新增后端接口或前端页面时，应先避免明显低效设计，再通过日志、慢查询和接口耗时定位具体瓶颈。

## 一、后端接口

- 列表接口必须分页，避免一次性返回大数据量。
- 分页查询必须有稳定排序字段。
- 查询条件字段应与数据库索引设计配合。
- Controller 不做复杂循环查询，聚合逻辑放到 Service 并尽量批量处理。
- MyBatis-Plus / MPJ 查询优先选择需要字段，避免无意义大对象传输。

## 二、数据库查询

- 高频查询字段应建立合适索引。
- 联合索引遵循最左前缀原则。
- 避免在 WHERE 条件中对索引字段做函数转换。
- 模糊查询避免前置 `%`。
- 大表分页、导出和统计应单独评估执行计划。

## 三、缓存使用

- 字典、配置、枚举、低频变更的热点数据可使用缓存。
- 缓存必须有 TTL 或主动失效机制。
- 不为强一致交易数据随意加缓存。
- 多租户缓存 key 必须包含租户维度。

## 四、前端页面

- 列表页使用分页和服务端查询，不在前端全量过滤大数据。
- 动态表格只渲染必要列，列设置变更后避免频繁刷新整页。
- 大弹窗、大表单拆分加载时要保留明确加载状态。
- 导入导出、报表、打印等长耗时任务要使用异步任务或进度反馈。

## 五、定位流程

1. 确认是前端渲染慢、网关慢、服务慢还是数据库慢。
2. 查看浏览器 Network 的接口耗时和响应大小。
3. 查看服务日志、慢查询日志和异常堆栈。
4. 对可疑 SQL 执行 EXPLAIN。
5. 优先修正查询条件、索引和批量逻辑，再考虑缓存。
