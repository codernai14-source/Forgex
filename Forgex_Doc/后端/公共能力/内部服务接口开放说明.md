# 内部服务接口开放说明

> 适用范围：Forgex 体系内模块间调用的内部服务契约
> 版本：**V0.8.5**
> 更新时间：**2026-08-12**

本文说明的“内部服务接口”，是指 Forgex 各业务模块之间直接调用的接口契约，不是第三方系统接入接口。第三方系统仍然统一走 `Forgex_Integration` 对应的接口平台、鉴权和调用流程。

> **模块归属已变更**：契约不再集中存放在单体 `Forgex_Common` 源码树。请同时阅读 [Common 模块化拆分与二开指南](./Common模块化拆分与二开指南.md)。

## 一、定位

- 内部服务接口用于 Forgex 各模块之间的数据读取、状态同步和能力复用。
- **Java 包名仍可保持** `com.forgex.common.api.*`，但 **Maven 归属按提供方拆分**：
  - 共享 DTO / 必要注解 → `Forgex_Domain_Contract`
  - Feign Client → 对应提供方 `Forgex_{服务}_Api`
  - Feign Token 透传、部分运行时辅助 → `Forgex_Common_Web` / `Forgex_Common_Infra`
- 内部服务接口默认服务于“模块互调”，不作为第三方系统对接规范。

## 二、边界说明

### 2.1 内部服务接口

- 仅供 Forgex 项目内部服务调用。
- 典型场景包括：
  - `Forgex_Basic` 提供基础主数据给 `Forgex_Sys`、`Forgex_Integration`、`Forgex_Workflow` 等模块使用
  - `Forgex_Sys` 提供用户、部门、职位、角色等组织数据给其他模块使用
  - `Forgex_Workflow` 提供内部发起审批、超时扫描给业务服务 / Job 使用
- 接口契约强调稳定、清晰、可批量查询。

### 2.2 第三方系统接口

- 第三方系统接入统一走 `Forgex_Integration`。
- 第三方接口的授权、参数映射、调用日志、回调和编排能力，不放在内部服务契约中描述。
- 不要把第三方接入文档和内部服务契约混写到同一套说明里。

## 三、契约模块对照

| 提供方服务 | Maven Api 模块 | 典型 Feign |
|---|---|---|
| Auth | `Forgex_Auth_Api` | `AuthFeignClient`、`AuthPermClient` |
| Sys | `Forgex_Sys_Api` | `SysUserFeignClient`、`SysTenantFeignClient`、`EncodeRuleFeignClient` |
| Basic | `Forgex_Basic_Api` | `BasicSupplierQueryFeignClient`、`BasicUnitConversionFeignClient` 等 |
| Job | `Forgex_Job_Api` | `CalendarReminderFeignClient` |
| Workflow | `Forgex_Workflow_Api` | `WorkflowExecutionFeignClient` |
| Integration | `Forgex_Integration_Api` | `IntegrationInternal*FeignClient` |
| 共享 DTO | `Forgex_Domain_Contract` | `UserInfoDTO`、`WorkflowExecutionStartRequestDTO`、主数据 Aggregate/Sync DTO 等 |

消费方 POM 示例：

```xml
<dependency>
  <groupId>com.forgex</groupId>
  <artifactId>Forgex_Workflow_Api</artifactId>
  <version>${project.version}</version>
</dependency>
<dependency>
  <groupId>com.forgex</groupId>
  <artifactId>Forgex_Domain_Contract</artifactId>
  <version>${project.version}</version>
</dependency>
```

## 四、基础信息模块接口范围

基础信息模块由 `Forgex_Basic` 负责，建议提供以下内部查询契约（Feign 在 `Forgex_Basic_Api`）：

### 4.1 物料信息

- 根据物料 ID 查询单条完整物料数据
- 根据物料编码查询单条完整物料数据
- 根据物料 ID 集合批量查询完整物料数据
- 根据物料编码集合批量查询完整物料数据

返回内容建议包含物料主数据、扩展信息、状态信息、创建/更新信息等完整字段，不只返回列表页摘要字段。

### 4.2 供应商信息

- 根据供应商 ID 查询单条完整供应商数据
- 根据供应商编码查询单条完整供应商数据
- 根据供应商 ID 集合批量查询完整供应商数据
- 根据供应商编码集合批量查询完整供应商数据

返回内容建议包含供应商主数据、联系人、资质、状态、创建/更新信息等完整字段。

### 4.3 客户信息

- 根据客户 ID 查询单条完整客户数据
- 根据客户编码查询单条完整客户数据
- 根据客户 ID 集合批量查询完整客户数据
- 根据客户编码集合批量查询完整客户数据

返回内容建议包含客户主数据、联系人、开票信息、扩展信息、状态、创建/更新信息等完整字段。

## 五、系统管理模块接口范围

系统管理模块由 `Forgex_Sys` 负责，建议提供以下内部查询契约（Feign 在 `Forgex_Sys_Api`）：

### 5.1 用户信息

- 根据用户 ID 查询单条完整用户数据
- 根据用户编码查询单条完整用户数据
- 根据用户 ID 集合批量查询完整用户数据
- 根据用户编码集合批量查询完整用户数据
- 根据角色 / 职位 / 部门 ID 或编码查询关联用户
- **按发起人解析第 N 级直属上级用户 ID**（工作流 `ApproverType.SUPERIOR` 使用）
  - 接口：`POST /sys/user/internal/resolveSuperiorUserIds`
  - 请求字段：`initiatorUserId`、`level`（可选，默认 1）、`tenantId`（内部调用场景）
  - 字段来源：`sys_user.superior_user_id`

### 5.2 组织数据

- 部门、职位、角色的单条 / 批量查询契约按业务需要扩展，保持与用户契约同一归属规则。

## 六、工作流内部接口范围

工作流模块由 `Forgex_Workflow` 负责，Feign 在 `Forgex_Workflow_Api`：

| 能力 | Feign 方法 | 服务端路径 |
|---|---|---|
| 内部发起审批 | `startExecution` | `POST /wf/execution/internal/start` |
| 超时扫描 | `scanTimeoutInstances` | `POST /wf/execution/internal/timeout/scan` |

超时扫描通常由 Job 处理器 `workflowTimeoutScanJob` 按租户触发，详见 [任务调度使用方式](../模块专题/任务调度使用方式.md) 与 [工作流使用方式](../模块专题/工作流使用方式.md)。

## 七、使用约定

1. 优先依赖提供方 `*_Api` 的 Feign Client，不自己手写重复 HTTP 调用。
2. 能批量就批量，减少频繁远程请求。
3. 调用方只关心契约，不直接依赖提供方内部 Service/Mapper。
4. 新增契约时同步更新本说明与 [Common 模块化拆分与二开指南](./Common模块化拆分与二开指南.md)。
5. 内部服务契约只描述“怎么让 Forgex 其他模块调用”，不要混入第三方授权、回调、编排等接口平台内容。
