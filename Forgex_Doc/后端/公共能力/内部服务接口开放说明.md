# 内部服务接口开放说明

> 适用范围：Forgex 体系内模块间调用的内部服务契约

本文说明的“内部服务接口”，是指 Forgex 各业务模块之间直接调用的接口契约，不是第三方系统接入接口。第三方系统仍然统一走 `Forgex_Integration` 对应的接口平台、鉴权和调用流程。

## 一、定位

- 内部服务接口用于 Forgex 各模块之间的数据读取、状态同步和能力复用。
- 对外暴露的契约统一放在 `Forgex_Common/src/main/java/com/forgex/common/api` 下。
- 其中：
  - `com.forgex.common.api.dto` 存放内部服务共享 DTO
  - `com.forgex.common.api.feign` 存放内部服务 Feign Client
- 内部服务接口默认服务于“模块互调”，不作为第三方系统对接规范。

## 二、边界说明

### 2.1 内部服务接口

- 仅供 Forgex 项目内部服务调用。
- 典型场景包括：
  - `Forgex_Basic` 提供基础主数据给 `Forgex_Sys`、`Forgex_Integration`、`Forgex_Workflow` 等模块使用
  - `Forgex_Sys` 提供用户、部门、职位、角色等组织数据给其他模块使用
- 接口契约强调稳定、清晰、可批量查询。

### 2.2 第三方系统接口

- 第三方系统接入统一走 `Forgex_Integration`。
- 第三方接口的授权、参数映射、调用日志、回调和编排能力，不放在内部服务契约中描述。
- 不要把第三方接入文档和内部服务契约混写到同一套说明里。

## 三、基础信息模块接口范围

基础信息模块由 `Forgex_Basic` 负责，建议提供以下内部查询契约：

### 3.1 物料信息

- 根据物料 ID 查询单条完整物料数据
- 根据物料编码查询单条完整物料数据
- 根据物料 ID 集合批量查询完整物料数据
- 根据物料编码集合批量查询完整物料数据

返回内容建议包含物料主数据、扩展信息、状态信息、创建/更新信息等完整字段，不只返回列表页摘要字段。

### 3.2 供应商信息

- 根据供应商 ID 查询单条完整供应商数据
- 根据供应商编码查询单条完整供应商数据
- 根据供应商 ID 集合批量查询完整供应商数据
- 根据供应商编码集合批量查询完整供应商数据

返回内容建议包含供应商主数据、联系人、资质、状态、创建/更新信息等完整字段。

### 3.3 客户信息

- 根据客户 ID 查询单条完整客户数据
- 根据客户编码查询单条完整客户数据
- 根据客户 ID 集合批量查询完整客户数据
- 根据客户编码集合批量查询完整客户数据

返回内容建议包含客户主数据、联系人、开票信息、扩展信息、状态、创建/更新信息等完整字段。

## 四、系统管理模块接口范围

系统管理模块由 `Forgex_Sys` 负责，建议提供以下内部查询契约：

### 4.1 用户信息

- 根据用户 ID 查询单条完整用户数据
- 根据用户编码查询单条完整用户数据
- 根据用户 ID 集合批量查询完整用户数据
- 根据用户编码集合批量查询完整用户数据
- 根据角色 ID 或角色编码查询关联用户数据
- 根据角色 ID 集合或角色编码集合批量查询关联用户数据
- 根据职位 ID 或职位编码查询关联用户数据
- 根据职位 ID 集合或职位编码集合批量查询关联用户数据
- 根据部门 ID 或部门编码查询关联用户数据
- 根据部门 ID 集合或部门编码集合批量查询关联用户数据

说明：

- 用户“编码”字段应以系统现有唯一编码口径为准，当前实现若以 `account` 承载，则沿用该字段作为对外查询条件。
- 组织维度查询返回的是“匹配到的用户完整数据集合”，不是角色/部门/职位本身的主数据。

### 4.2 部门信息

- 根据部门 ID 查询单条完整部门数据
- 根据部门编码查询单条完整部门数据
- 根据部门 ID 集合批量查询完整部门数据
- 根据部门编码集合批量查询完整部门数据

### 4.3 职位信息

- 根据职位 ID 查询单条完整职位数据
- 根据职位编码查询单条完整职位数据
- 根据职位 ID 集合批量查询完整职位数据
- 根据职位编码集合批量查询完整职位数据

### 4.4 角色信息

- 根据角色 ID 查询单条完整角色数据
- 根据角色编码查询单条完整角色数据
- 根据角色 ID 集合批量查询完整角色数据
- 根据角色编码集合批量查询完整角色数据

## 五、接口契约建议

- 单条查询和批量查询尽量分开定义，避免一个接口塞进过多分支判断。
- 批量查询优先使用请求体承载 ID 或编码集合。
- 返回类型优先保持统一，建议使用 `R<T>` 包装。
- 接口说明、DTO 字段和方法名要同步维护 `@Schema`、`@Operation` 等注解。
- 内部服务契约只描述“怎么让 Forgex 其他模块调用”，不要混入第三方授权、回调、编排等接口平台内容。
