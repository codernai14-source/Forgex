# 业务编码生成（使用方式）

> 分类：后端 / 公共能力  
> 版本：**V0.6.6**  
> 更新时间：**2026-05-17**

本文说明业务模块如何按「编码规则」生成唯一业务单号，规则定义在 Sys 模块（表 `fx_encode_rule`），业务侧通过 **Common 封装** 发起远程调用，无需直接依赖 Sys 实现类。

## 代码位置

| 说明 | 路径 |
|---|---|
| 静态入口（推荐多数 Service 使用） | `Forgex_MOM/Forgex_Backend/Forgex_Common/src/main/java/com/forgex/common/utils/EncodeUtils.java` |
| 封装服务 | `Forgex_MOM/Forgex_Backend/Forgex_Common/src/main/java/com/forgex/common/service/EncodeRuleService.java` |
| Feign 定义 | `Forgex_MOM/Forgex_Backend/Forgex_Common/src/main/java/com/forgex/common/feign/client/EncodeRuleFeignClient.java` |
| 远端实现 | `Forgex_Sys` 模块（接口路径见 Feign：`POST /sys/encodeRule/feign/generate`） |

## 前置条件

1. 当前业务服务已依赖 `Forgex_Common`，并启用 **OpenFeign**（能扫描到 `EncodeRuleFeignClient`）。
2. 在 Sys 管理端或初始化脚本中，已为 `ruleCode` 配置并启用对应编码规则。
3. 应用已正常启动，`EncodeUtils` 通过 `@Component` 完成静态字段注入；禁止在未启动 Spring 容器的单元测试里直接调用静态方法（会报「未初始化」）。

## 使用方式一：`EncodeUtils.nextEncode`（推荐）

在任意 Spring 管理的 **Service / Component** 中，于需要生成编码的业务点直接调用：

```java
import com.forgex.common.utils.EncodeUtils;

// ...

/**
 * 保存订单前生成单据编号。
 *
 * @return 新生成的订单号
 */
public String allocateOrderNo() {
    // ruleCode 必须与 fx_encode_rule 中配置一致，例如 SALE_ORDER、PURCHASE_ORDER
    return EncodeUtils.nextEncode("SALE_ORDER");
}
```

### 行为说明

- `ruleCode` 为空：抛出 `IllegalArgumentException`（在 `EncodeRuleService` 层校验）。
- Feign 未注入：抛出 `IllegalStateException`，提示编码服务未启用。
- 远程返回非成功：抛出 `RuntimeException`，消息中带 Sys 返回说明。

## 使用方式二：注入 `EncodeRuleService`

若希望在同一类中 mock 或封装多条规则，可注入 `EncodeRuleService`：

```java
import com.forgex.common.service.EncodeRuleService;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;

/**
 * 示例：通过服务 Bean 生成编码。
 */
@Service
@RequiredArgsConstructor
public class DemoEncodeConsumer {

    private final EncodeRuleService encodeRuleService;

    /**
     * 生成采购单号。
     *
     * @return 采购单号
     */
    public String nextPurchaseNo() {
        return encodeRuleService.generateCode("PURCHASE_ORDER");
    }
}
```

## 使用方式三：直接 Feign（不推荐业务层常用）

仅在极少数无法使用 `EncodeUtils` / `EncodeRuleService` 的场景下，再在业务模块注入 `EncodeRuleFeignClient`，自行处理 `R<String>` 与 `StatusCode`（与 `EncodeRuleService` 逻辑重复，易遗漏错误处理）。

## 与网关、多租户

编码生成走 Sys 服务；请求的租户上下文需与普通业务接口一致（由网关与 Common 拦截器传递），以便按租户隔离序列或规则。
