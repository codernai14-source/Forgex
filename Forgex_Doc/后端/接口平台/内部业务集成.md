# 内部业务集成

> 分类：后端 / 接口平台 / 内部编排  
> 版本：**V1.0.0**

源码为 `InternalCustomerIntegrationController`、`InternalEmployeeIntegrationController`、`InternalMaterialIntegrationController`、`InternalSupplierIntegrationController`、`InternalUserIntegrationController`，统一通过 `IntegrationFacade` 调用第三方，并用对应 Feign 客户端写回基础数据模块。

## 已实现入口

各控制器均提供 `POST /internal/{customer|employee|material|supplier|user}/sync` 和 `/pull`。请求包含 `tenantId`、`apiCode`、可选 `payload`；sync 先导出本租户聚合数据，pull 先调用第三方再把结果转换为聚合 DTO 写回。用户拉取示例：

```json
{
  "tenantId": "10001",
  "apiCode": "sys_user_pull",
  "payload": {"includeDisabled": true}
}
```

控制器会设置 `TenantContext`，执行 finally 清理；用户、物料等响应可为数组、`{data:[...]}` 或 `{users:[...]}`/`{materials:[...]}`，代码有对应解包逻辑。

## 注意事项

空数据会直接返回 0 条结果，不会调用第三方；同步返回数量只在 `IntegrationExecuteResult.isSuccess()` 时计入 updated。字段名称必须由参数映射决定，例如 ERP 的 `commonUsers.code` 对应 Forgex 的 `users.account`，不能要求控制器硬编码转换。

## 未完成能力

当前只有客户、员工、物料、供应商、用户五类编排，没有通用主数据编排器、增量游标、幂等键或冲突合并策略。下一步应在 Feign 契约中增加批次号/幂等键，再补失败重放和差异报告。
