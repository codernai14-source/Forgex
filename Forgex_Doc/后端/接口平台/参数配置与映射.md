# 参数配置与映射

> 分类：后端 / 接口平台 / 参数转换  
> 版本：**V1.0.0**

## 源码位置

`ApiParamConfigController`、`ApiParamMappingController`、`ApiParamConfigServiceImpl`、`ApiParamMappingServiceImpl`、`ApiParamAssemblerImpl`；前端组件为 `src/components/system/integration/ApiParamConfigDialog.vue`、`ApiParamMappingDialog.vue`。

## 参数树接口

| 方法 | 路径 |
|---|---|
| GET | `/api/integration/param-config/tree?apiConfigId=1&direction=REQUEST&outboundTargetId=2` |
| POST | `/api/integration/param-config/children`、`/create`、`/update`、`/delete/{id}`、`/batch-delete` |
| POST | `/api/integration/param-config/replace-tree` |

所有管理操作需要 `integration:api-config:config-param` 或 `integration:api-config:config-mapping`。

## 参数树规则

`fx_api_param_config` 用 `parentId` 组织树；`direction` 是 `REQUEST/RESPONSE`；`nodeType` 是 `OBJECT/ARRAY/FIELD`；`fieldPath` 是完整路径。`root` 只用于树结构，不是运行时字段。

```json
[
  {"fieldName":"root","fieldPath":"root","nodeType":"OBJECT","children":[
    {"fieldName":"users","fieldPath":"root.users","nodeType":"ARRAY","children":[
      {"fieldName":"code","fieldPath":"root.users.code","nodeType":"FIELD","fieldType":"STRING","required":1},
      {"fieldName":"name","fieldPath":"root.users.name","nodeType":"FIELD","fieldType":"STRING"}
    ]}
  ]}
]
```

可用前端解析真实 JSON 后整体替换：

```ts
import { parseApiParamJson, replaceApiParamTree } from '@/api/system/integration'
const tree = await parseApiParamJson({ jsonString: '{"commonUsers":[{"code":"U001","name":"Alice"}]}' })
await replaceApiParamTree({ apiConfigId: 10, direction: 'REQUEST', tree: tree.data })
```

## 映射字段

`sourceFieldPath` 与 `targetFieldPath` 必须存在于对应参数树；`targetScope` 为 `BODY/QUERY/HEADER/PATH`；`valueType` 为 `SOURCE/DEFAULT/CONSTANT`；`transformRule`、`defaultValue`、`constantValue` 按取值类型使用。

```ts
import { batchSaveApiParamMappings } from '@/api/system/integration'
await batchSaveApiParamMappings({
  apiConfigId: 10, outboundTargetId: 20, direction: 'OUTBOUND',
  mappings: [
    { apiConfigId: 10, sourceFieldPath: 'root.users.code', targetFieldPath: 'root.commonUsers.code', targetScope: 'BODY', valueType: 'SOURCE' },
    { apiConfigId: 10, sourceFieldPath: 'root.orderId', targetFieldPath: 'root.orderId', targetScope: 'PATH', valueType: 'SOURCE' },
    { apiConfigId: 10, sourceFieldPath: 'root.pageNo', targetFieldPath: 'root.page', targetScope: 'QUERY', valueType: 'DEFAULT', defaultValue: '1' },
  ],
})
```

数组必须映射到叶子字段，例如 `root.users.code -> root.commonUsers.code`；只映射 `users -> commonUsers` 不能证明字段结构正确。入站用 `INBOUND`，出站请求用 `OUTBOUND`，出站响应回写也由出站定义的响应映射处理。

## 实现流程和错误处理

`ApiParamAssemblerImpl` 先读取快照中的树和映射，解析来源路径，执行默认值/常量/转换规则，再分别写入 body、query、headers、pathVariables。找不到字段路径、类型转换失败或数组层级不一致时，组装结果可能缺字段；调用日志的 `assembledRequestData` 是首要证据。当前保存接口没有完整的第三方语义校验，联调前必须用真实 JSON 导入并检查每一行映射。

## 二次开发

新增转换规则应在 assembler 中增加可测试的纯函数，并同时补充前端可选项；不要在 Controller 里临时改字段名。若要支持表达式或脚本，必须加入超时、白名单和异常隔离，当前源码没有脚本执行能力。
