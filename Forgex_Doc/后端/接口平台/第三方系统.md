# 第三方系统

> 分类：后端 / 接口平台 / 第三方系统  
> 版本：**V1.0.0**

## 源码与接口

源码：`ThirdSystemController.java`、`ThirdSystemServiceImpl.java`、`ThirdSystemDTO.java`；前端：`src/views/integrationPlatform/thirdSystem` 与 `src/api/system/integration.ts`。接口权限为 `integration:third-system:view/add/edit/delete/batch-delete`。

| 方法 | 路径 |
|---|---|
| POST | `/api/integration/third-system/page`、`/list`、`/create`、`/update`、`/batch-delete` |
| GET | `/api/integration/third-system/detail/{id}` |
| POST | `/api/integration/third-system/delete/{id}` |

## 创建示例

```ts
import { addThirdSystem, listThirdSystems } from '@/api/system/integration'
await addThirdSystem({ systemCode: 'erp-main', systemName: 'ERP 主系统', ipAddress: '192.168.3.7:18080', status: 1 })
const systems = await listThirdSystems({ status: 1 })
```

`systemCode` 是平台内稳定标识；`ipAddress` 保存主机和端口，出站目标的 `targetUrl` 保存相对路由。服务按编码校验唯一性，更新时排除当前 ID。删除是逻辑删除，存在关联授权时服务会拒绝删除；批量删除任一项失败会整体回滚。

## 推荐流程和排错

先创建系统，再创建授权，再在出站目标中填写 `thirdSystemId`。如果详情存在但列表不可见，检查租户、状态和逻辑删除字段；如果删除失败，先删除或迁移授权记录。不要把 Token、密码或完整授权配置放在第三方系统备注中。

## 二开边界

当前模型只保存地址、联系人、状态和备注，不负责探活、证书管理或连接池。新增探活能力应由独立健康检查服务实现，避免在 CRUD 请求中同步访问第三方。
