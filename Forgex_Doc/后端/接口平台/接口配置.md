# 接口配置

> 分类：后端 / 接口平台 / 配置  
> 版本：**V1.0.0**

## 功能定位

接口配置决定接口编码、方向、调用方式、处理器或目标地址，是参数树、映射和运行时快照的父对象。源码：`Forgex_Integration/controller/ApiConfigController.java`、`domain/dto/ApiConfigDTO.java`、`service/impl/ApiConfigServiceImpl.java`；Web 页面：`src/views/integrationPlatform/apiConfig`，API：`src/api/system/integration.ts`。

## 接口清单

权限码均来自 `ApiConfigController`：`integration:api-config:view/add/edit/delete`。

## 字段和配置规则

```ts
import { addApiConfig } from '@/api/system/integration'

const created = await addApiConfig({
  apiCode: 'erp_user_sync',
  apiName: 'ERP 用户同步',
  direction: 'OUTBOUND',
  callMethod: 'HTTP',
  httpMethod: 'POST',
  contentType: 'application/json',
  invokeMode: 'SYNC',
  timeoutMs: 10000,
  retryCount: 2,
  retryIntervalMs: 500,
  moduleCode: 'basic',
  status: 1,
  outboundTargets: [{
    targetCode: 'erp-main', targetName: 'ERP 主系统',
    targetUrl: '/api/users/sync', httpMethod: 'POST',
    contentType: 'application/json', invokeMode: 'SYNC', status: 1,
  }],
})
```

`direction` 只有 `INBOUND/OUTBOUND`；入站通常填写 `apiPath`、`processorBean`，出站填写目标和目标列表。一个出站配置可以有多个目标，运行时按目标顺序执行；没有目标时会走兼容的默认目标地址链路。接口停用后快照不会被正常执行，更新后由 `ApiDefinitionServiceImpl` 重新编译并刷新缓存。

## 高阶用法：同一接口多目标

为同一 `apiConfigId` 增加多个 `outboundTargets`，每个目标独立设置 URL、超时、重试和同步/异步模式。调用返回 `syncResults` 与 `asyncResults`，同步目标全部成功才会把总状态标记为 `SUCCESS`；存在失败时是 `PARTIAL_FAIL` 或失败结果。不要把多个第三方 URL 拼在一个 `targetUrl` 中。

## 实现流程

保存时服务校验编码、方向和必要字段，持久化 `fx_api_config` 及出站目标；读取时 `ApiDefinitionServiceImpl` 聚合接口、目标、参数和映射为 `ApiDefinitionSnapshot`，缓存键为 `integration:definition:{tenantId}:{direction}:{apiCode}`。网关每次按 `apiCode + direction` 读取快照，避免请求过程中重复查询多张配置表。

## 常见错误

- **编码重复**：同租户已有相同 `apiCode`，读取详情后携带 `id` 更新。
- **出站无目标**：配置目标或确认兼容的 `targetUrl`、`httpMethod` 已填写；多目标调用不能只保存主表。
- **入站处理器未配置**：`processorBean` 必须对应 `ApiInterpreterRegistry` 已注册的 Bean，否则返回 `API_HANDLER_NOT_CONFIGURED`。
- **改了配置但调用仍旧**：确认服务刷新/重载快照；不要直接改表后期待缓存立即变化。

## 二次开发边界

新增字段需同步 Entity、DTO、Param、前端类型、快照编译和执行器；仅加数据库列不会参与运行时。新增调用协议不能复用 HTTP 执行器的假设，应扩展 `ApiOutboundExecutor` 并保留日志字段。当前没有通用配置校验预览接口，建议二开时先实现 dry-run，再允许启用。
