# 错误处理与国际化

> 分类：后端 / 接口平台 / 错误处理  
> 版本：**V1.0.0**

接口平台错误来自 `IntegrationPromptEnum`，通过 `I18nBusinessException`、`R.fail` 和 `fx_i18n_message` 输出。不要在 Controller 或执行器写死中文。

## 常见错误

| 场景 | 典型提示 | 首要检查 |
|---|---|---|
| 接口不存在 | `API_CONFIG_NOT_FOUND` | apiCode、方向、租户 |
| 入站鉴权失败 | `API_AUTH_FAILED` | Token、白名单、thirdSystemId |
| 处理器未注册 | `API_HANDLER_NOT_CONFIGURED` | processorBean 与注册表 |
| 入站执行失败 | `API_INBOUND_EXECUTE_FAILED` | 参数组装和处理器异常 |
| 出站执行失败 | `API_OUTBOUND_EXECUTE_FAILED` | URL、映射、超时和响应 |
| 异步任务不存在 | `API_TASK_NOT_FOUND` | taskId 和结果表 |
| 日志不存在 | `CALL_LOG_NOT_FOUND` | id 与 callTime 月表 |

## 推荐调用方处理

```ts
try {
  const result = await integrationApi.getApiConfigDetail(id)
  // http.ts 已按 R<T> 解包；业务只消费 result.data
} catch (error) {
  // 保留 traceId/taskId，交给统一错误提示，不在页面重复 message.success/error
  console.error('integration request failed', error)
}
```

生产环境必须为 `module='integration'` 的提示码配置五语言文案，并确认 `forgex_common.fx_i18n_message` 可被服务访问。当前源码允许底层异常文本进入日志或提示兜底，二开应对第三方原文脱敏并将可重试、不可重试错误分类。
