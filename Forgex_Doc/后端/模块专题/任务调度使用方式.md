# 任务调度使用方式

> 分类：后端 / 模块专题
> 版本：**V0.6.5**
> 更新时间：**2026-04-17**

本文档说明任务调度模块的使用建议。

## 推荐实践

1. 新增可集中管理的定时任务时，优先注册到 `Forgex_Job`，不要再引入 Snail-Job、XXL-Job、Quartz 等第三方调度框架。
2. 首期任务处理器建议使用 Java Bean 方式暴露，方法签名保持简单，并通过任务上下文接收参数。
3. 任务涉及租户、用户、语言时，执行前恢复上下文，执行后必须清理上下文。
4. 任务结果通知尽量复用消息模板和 SSE 能力。
5. 高频短周期任务、连接保活任务和授权刷新任务默认保留在原模块，迁移前必须评估故障半径。
6. Cron 表达式按 Spring `CronExpression` 支持范围校验，不能按 Quartz 全量语法承诺。

## 常见排查

| 现象 | 排查点 |
|---|---|
| 任务不执行 | 调度开关、任务状态、`next_trigger_time`、Cron 表达式、Job 服务是否在线 |
| 多实例重复执行 | Redisson 锁 Key、锁租约、实例时间是否一致 |
| 任务上下文错乱 | TenantContext / UserContext / LangContext 是否设置和清理 |
| 日志无记录 | 执行前是否创建 `sys_job_log`，异常分支是否更新日志状态 |
| 通知不发送 | 消息模板、SSE、下游服务、告警静默期 |
