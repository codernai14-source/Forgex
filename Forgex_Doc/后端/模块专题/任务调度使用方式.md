# 任务调度使用方式

> 分类：后端 / 模块专题
> 版本：**V0.6.5**
> 更新时间：**2026-04-17**

本文档说明任务调度模块的使用建议。

## 访问入口

1. 前端菜单入口固定在 `系统管理` 模块下的一级目录 `定时任务`，不是主页目录，也不单独创建顶级 Job 模块。
2. 当前页面包括：任务大盘、任务管理、执行日志、执行器实例、重试/死信、告警规则、告警日志、DAG 编排。
3. 前端请求统一走网关模块前缀：`/api/job/...`。这里的 `job` 来自服务名 `forgex-job` 去掉 `forgex-` 前缀，不需要在网关里为每个业务接口单独加路由。
4. Job 后端服务本地 `server.servlet.context-path` 是 `/job`，通过网关访问时示例为 `/api/job/dashboard/summary`、`/api/job/task/page`。

## Java Bean 任务

Java Bean 任务适合需要使用 Forgex 内部能力、Feign 客户端、租户上下文或复杂业务编排的任务。任务处理器由 `Forgex_Job` 服务内的 Spring 容器加载，任务定义中的 `beanName` 必须能在 `Forgex_Job` 应用上下文中找到。

### 处理器写法

```java
package com.forgex.job.core.handler;

import com.forgex.job.annotation.FxJobHandler;
import com.forgex.job.core.executor.JobExecutionContext;
import com.forgex.job.core.executor.JobResult;

/**
 * 接口调用日志清理任务。
 */
@FxJobHandler("integrationCallLogCleanJob")
public class IntegrationCallLogCleanJob {

    public JobResult execute(JobExecutionContext context) {
        String params = context.getParams();
        // 解析 params，调用 Feign 或 Service 完成业务处理。
        return JobResult.success("clean success");
    }
}
```

支持的方法签名：

```java
JobResult execute(JobExecutionContext context)
void execute(JobExecutionContext context)
```

如果方法返回 `void`，调度器默认按成功处理；如果抛出异常，日志会记录失败并按任务配置进入重试。

### 任务配置

在 `任务管理` 新增任务时选择：

| 字段 | 填写说明 |
|---|---|
| 任务类型 | `JavaBean` |
| Bean 名称 | Spring Bean 名称，例如 `integrationCallLogCleanJob` |
| 方法名 | 可空，默认 `execute` |
| 调度类型 | `Cron`、`固定间隔` 或 `手动` |
| Cron 表达式 | 使用 Spring `CronExpression` 能力范围 |
| 任务参数 | JSON 字符串，通过 `context.getParams()` 读取 |
| 最大重试次数 | 失败后写入重试/死信流程 |

### 冒烟测试 Bean

`Forgex_Job` 内置了一个 Java Bean 测试处理器，用于验证任务配置、手动触发、日志、失败、异常和超时链路：

| 配置项 | 值 |
|---|---|
| 任务类型 | `JavaBean` |
| Bean 名称 | `jobSmokeTestHandler` |
| 方法名 | `execute` |
| 调度类型 | `手动` |
| 超时时间 | 建议 `10` 秒 |
| 最大重试次数 | 建议 `1` |

可用任务参数：

```json
{"mode":"success","message":"manual smoke test"}
```

```json
{"mode":"fail"}
```

```json
{"mode":"exception"}
```

```json
{"mode":"sleep","sleepMs":3000}
```

如果要验证超时，把任务超时时间改为 `1` 秒，再使用 `{"mode":"sleep","sleepMs":3000}` 手动触发。测试任务建议保持停用，只通过手动触发验证链路。

## 其它模块如何接入

`Forgex_Job` 是独立微服务，不能直接从 `Forgex_Sys`、`Forgex_Integration`、`Forgex_Basic` 等其它服务的 Spring 容器里拿 Bean。其它模块接入定时任务有两种方式：

1. 推荐方式：在 `Forgex_Job` 内新增一个调度适配 Bean，适配 Bean 通过 Feign 客户端调用目标业务模块。这样调度、日志、重试在 Job 服务闭环，业务逻辑仍保留在原模块。
2. HTTP 方式：目标模块提供内部接口，在 Job 任务里配置 HTTP URL。生产环境必须配置 HTTP 白名单，避免任意地址调用。

示例：`Forgex_Integration` 需要定时清理调用日志时，不要把 Integration 的 Service 直接搬进 Job 服务；应在 `Forgex_Job` 写 `IntegrationCallLogCleanJob`，通过 Integration Feign 或内部 HTTP 接口触发清理。

## HTTP 任务

HTTP 任务适合调用已有模块接口或外部可信服务。配置要求：

1. `httpUrl` 必须命中 `forgex.job.security.http-whitelist`。
2. `httpMethod` 支持常见 HTTP 方法，建议优先使用 `POST`。
3. 请求头 JSON 写入 `httpHeaders`，任务参数写入 `jobParams`。
4. 接口需要幂等，手动触发和重试可能多次调用同一业务动作。

## 脚本任务

脚本任务默认关闭。启用前必须在 Nacos `job.yml` 配置：

```yaml
forgex:
  job:
    security:
      script-enabled: true
      script-directory-whitelist:
        - "D:/forgex/scripts"
```

脚本执行会记录命令、参数、工作目录、退出码和截断输出。脚本目录不在白名单内时任务直接失败。

## 推荐实践

1. 新增可集中管理的定时任务时，优先注册到 `Forgex_Job`，不要再引入 Snail-Job、XXL-Job、Quartz 等第三方调度框架。
2. 首期任务处理器建议使用 Java Bean 方式暴露，方法签名保持简单，并通过任务上下文接收参数。
3. 任务涉及租户、用户、语言时，执行前恢复上下文，执行后必须清理上下文。
4. 任务结果通知尽量复用消息模板和 SSE 能力。
5. 高频短周期任务、连接保活任务和授权刷新任务默认保留在原模块，迁移前必须评估故障半径。
6. Cron 表达式按 Spring `CronExpression` 支持范围校验，不能按 Quartz 全量语法承诺。

## 常见排查

| 现象 | 排查点 |
|---|---|
| 任务不执行 | 调度开关、任务状态、`next_trigger_time`、Cron 表达式、Job 服务是否在线 |
| 多实例重复执行 | Redisson 锁 Key、锁租约、实例时间是否一致 |
| 任务上下文错乱 | TenantContext / UserContext / LangContext 是否设置和清理 |
| 日志无记录 | 执行前是否创建 `sys_job_log`，异常分支是否更新日志状态 |
| 通知不发送 | 消息模板、SSE、下游服务、告警静默期 |
| Bean 找不到 | `beanName` 是否在 `Forgex_Job` 服务内注册，是否误填了其它微服务的 Bean |
| 网关提示接口不存在 | 前端是否请求 `/api/job/...`，服务名是否为 `forgex-job`，Job 服务是否已注册到 Nacos |
