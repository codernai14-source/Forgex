# 集成平台使用方式

> 分类：后端 / 模块专题
> 版本：V0.6.5
> 说明：本文描述当前接口平台标准接入方式，已覆盖 2026-05 调用日志专项修复内容。

## 1. 配置顺序

建议按以下顺序完成配置：

1. 新增第三方系统 `ThirdSystem`。
2. 配置第三方鉴权 `ThirdAuthorization`。
3. 新增接口配置 `ApiConfig`。
4. 如为出站接口，配置出站目标 `ApiOutboundTarget`。
5. 配置参数结构 `ApiParamConfig`。
6. 配置字段映射 `ApiParamMapping`。
7. 如为入站接口，补充处理器 Bean。
8. 联调并通过调用日志、任务结果验证执行结果。

## 2. 内部服务如何调用外部接口

内部统一注入 `IntegrationFacade`：

```java
@Resource
private IntegrationFacade integrationFacade;

public void demo() {
    DemoRequest request = new DemoRequest();
    request.setOrderNo("SO20260507001");

    IntegrationExecuteResult result = integrationFacade.invoke("ERP_ORDER_PUSH", request);
}
```

平台内部会自动完成：

1. 查接口定义快照。
2. 将请求实体转换为 `Map`。
3. 组装 `body/query/header/pathVariables`。
4. 调用第三方接口。
5. 记录原始参数、组装参数、响应结果、耗时和目标系统信息。

## 3. 外部系统如何调用平台

### 3.1 统一入口

外部统一调用：

- `POST /api/integration/public/invoke`

请求体中只有 `jiekou_code` 是保留字段，其余字段会原样进入业务 `payload`。

示例：

```json
{
  "jiekou_code": "sys_user_third_party_inbound",
  "token": "abc123",
  "tenantId": 10001,
  "users": [
    {
      "userCode": "U001",
      "userName": "Alice",
      "phone": "13800000000"
    }
  ]
}
```

说明：

- `jiekou_code`：接口编码，必传。
- `token`：如启用 token 鉴权则传。
- 其余字段不做字段名白名单限制，全部进入 `payload`。

### 3.2 异步结果查询

如接口配置为异步，外部通过以下接口查询结果：

- `GET /api/integration/public/task/{taskId}`

## 4. 参数结构如何配置

数据库表 `fx_api_param_config` 用于定义参数树。

关键字段说明：

- `parent_id`：父节点 ID，用于组织树结构。
- `direction`：`REQUEST` 或 `RESPONSE`。
- `node_type`：`OBJECT`、`ARRAY`、`FIELD`。
- `field_name`：字段名。
- `field_path`：完整路径。

推荐约定：

- 根节点通常用 `root`，类型为 `OBJECT`。
- 对象节点配置为 `OBJECT`。
- 数组或集合节点配置为 `ARRAY`。
- 普通字段配置为 `FIELD`。

### 4.1 对象示例

```text
root                 OBJECT
root.user            OBJECT
root.user.userCode   FIELD
root.user.userName   FIELD
```

### 4.2 集合对象数组示例

```text
root                    OBJECT
root.users              ARRAY
root.users.userCode     FIELD
root.users.userName     FIELD
root.users.phone        FIELD
```

说明：

- `root.users` 表示整个数组节点。
- 子字段继续挂在该数组节点下。
- 平台当前按树关系和路径解析，不要求额外配置 `[]` 字符。

## 5. 双方字段如何对接

数据库表 `fx_api_param_mapping` 用于定义来源字段到目标字段的映射关系。

关键字段：

- `source_field_path`
- `target_field_path`
- `target_scope`
- `value_type`
- `transform_rule`
- `default_value`
- `constant_value`

### 5.1 目标区域说明

- `BODY`：写入请求体。
- `QUERY`：写入 URL 查询参数。
- `HEADER`：写入请求头。
- `PATH`：替换路径变量。

### 5.2 取值类型说明

- `SOURCE`：取来源字段值。
- `DEFAULT`：使用默认值。
- `CONSTANT`：使用常量值。

### 5.3 映射示例

```text
tenantId -> tenant_id          BODY   SOURCE
users -> data.users            BODY   SOURCE
token -> Authorization         HEADER SOURCE
orderId -> orderId             PATH   SOURCE
pageNo -> page                 QUERY  DEFAULT
systemCode -> sysCode          BODY   CONSTANT
```

## 6. 调用日志如何查看

调用日志管理接口：

- `POST /api/integration/call-log/page`
- `POST /api/integration/call-log/list`
- `GET /api/integration/call-log/detail/{id}?callTime=...`
- `GET /api/integration/call-log/count`
- `GET /api/integration/call-log/success-rate`

重点字段：

- `trace_id`
- `task_id`
- `api_code`
- `raw_request_data`
- `assembled_request_data`
- `response_data`
- `result_type`
- `error_message`
- `outbound_target_id`
- `target_system_code`
- `target_system_name`

## 7. 调用日志月表维护规则

调用日志按月分表，命名固定为：

- `fx_api_call_log_yyyyMM`

维护规则：

1. 服务启动时自动确保当月表和下月表存在。
2. 每天定时检查当月表。
3. 每月最后一天提前创建下月表。
4. 写入日志前按 `callTime` 再兜底创建。
5. 查询时自动跳过不存在的历史月份表，避免缺表报错。

## 8. 排障建议

出现问题时按以下顺序排查：

1. 接口配置是否启用且方向正确。
2. 出站目标配置是否正确。
3. 参数结构和字段映射是否完整。
4. 入站处理器 Bean 是否存在。
5. 异步任务结果表是否有结果。
6. 调用日志中的原始参数、组装参数、错误信息是否完整。
