# 集成平台使用方式

> 分类：后端 / 模块专题
> 版本：V0.6.5
> 说明：本文描述当前接口平台标准接入方式，已覆盖 2026-05 调用日志专项修复内容。

## 1. 配置顺序

建议按以下顺序完成配置：

1. 新增第三方系统 `ThirdSystem`。
2. 配置第三方鉴权 `ThirdAuthorization`。
3. 新增接口配置 `ApiConfig`。
4. 如为出站接口，配置出站目标 `ApiOutboundTarget`。
5. 配置参数结构 `ApiParamConfig`。
6. 配置字段映射 `ApiParamMapping`。
7. 如为入站接口，补充处理器 Bean。
8. 联调并通过调用日志、任务结果验证执行结果。

## 2. 内部服务如何调用外部接口

内部统一注入 `IntegrationFacade`：

```java
@Resource
private IntegrationFacade integrationFacade;

public void demo() {
    DemoRequest request = new DemoRequest();
    request.setOrderNo("SO20260507001");

    IntegrationExecuteResult result = integrationFacade.invoke("ERP_ORDER_PUSH", request);
}
```

平台内部会自动完成：

1. 查接口定义快照。
2. 将请求实体转换为 `Map`。
3. 组装 `body/query/header/pathVariables`。
4. 调用第三方接口。
5. 记录原始参数、组装参数、响应结果、耗时和目标系统信息。

## 3. 外部系统如何调用平台

### 3.1 统一入口

外部统一调用：

- `POST /api/integration/public/invoke`

请求体中只有 `jiekou_code` 是保留字段，其余字段会原样进入业务 `payload`。

示例：

```json
{
  "jiekou_code": "sys_user_third_party_inbound",
  "token": "abc123",
  "tenantId": 10001,
  "users": [
    {
      "userCode": "U001",
      "userName": "Alice",
      "phone": "13800000000"
    }
  ]
}
```

说明：

- `jiekou_code`：接口编码，必传。
- `token`：如启用 token 鉴权则传。
- 其余字段不做字段名白名单限制，全部进入 `payload`。

### 3.2 异步结果查询

如接口配置为异步，外部通过以下接口查询结果：

- `GET /api/integration/public/task/{taskId}`

## 4. 参数结构如何配置

数据库表 `fx_api_param_config` 用于定义参数树。

关键字段说明：

- `parent_id`：父节点 ID，用于组织树结构。
- `direction`：`REQUEST` 或 `RESPONSE`。
- `node_type`：`OBJECT`、`ARRAY`、`FIELD`。
- `field_name`：字段名。
- `field_path`：完整路径。

推荐约定：

- 根节点通常用 `root`，类型为 `OBJECT`。
- 对象节点配置为 `OBJECT`。
- 数组或集合节点配置为 `ARRAY`。
- 普通字段配置为 `FIELD`。

### 4.1 对象示例

```text
root                 OBJECT
root.user            OBJECT
root.user.userCode   FIELD
root.user.userName   FIELD
```

### 4.2 集合对象数组示例

```text
root                    OBJECT
root.users              ARRAY
root.users.userCode     FIELD
root.users.userName     FIELD
root.users.phone        FIELD
```

说明：

- `root.users` 表示整个数组节点。
- 子字段继续挂在该数组节点下。
- 平台当前按树关系和路径解析，不要求额外配置 `[]` 字符。

## 5. 双方字段如何对接

数据库表 `fx_api_param_mapping` 用于定义来源字段到目标字段的映射关系。

关键字段：

- `source_field_path`
- `target_field_path`
- `target_scope`
- `value_type`
- `transform_rule`
- `default_value`
- `constant_value`

### 5.1 目标区域说明

- `BODY`：写入请求体。
- `QUERY`：写入 URL 查询参数。
- `HEADER`：写入请求头。
- `PATH`：替换路径变量。

### 5.2 取值类型说明

- `SOURCE`：取来源字段值。
- `DEFAULT`：使用默认值。
- `CONSTANT`：使用常量值。

### 5.3 映射示例

```text
tenantId -> tenant_id          BODY   SOURCE
users.userCode -> data.users.code BODY SOURCE
token -> Authorization         HEADER SOURCE
orderId -> orderId             PATH   SOURCE
pageNo -> page                 QUERY  DEFAULT
systemCode -> sysCode          BODY   CONSTANT
```

注意：

- `users -> data.users` 这类整包数组映射只能说明路由可能调通，不能证明字段对接正确。正式联调必须拆到数组对象内的叶子字段。
- 如果第三方实体类叫 `commonUsers`、账号字段叫 `code`，就必须配置 `root.users.account -> root.commonUsers.code`，不能要求第三方改成 Forgex 的 `users.account`。
- 页面中“来源类型/目标类型”来自参数树字段类型；如果为空，说明该映射路径未在请求或响应参数树中定义完整。

## 6. 调用日志如何查看

调用日志管理接口：

- `POST /api/integration/call-log/page`
- `POST /api/integration/call-log/list`
- `GET /api/integration/call-log/detail/{id}?callTime=...`
- `GET /api/integration/call-log/count`
- `GET /api/integration/call-log/success-rate`

重点字段：

- `trace_id`
- `task_id`
- `api_code`
- `raw_request_data`
- `assembled_request_data`
- `response_data`
- `result_type`
- `error_message`
- `outbound_target_id`
- `target_system_code`
- `target_system_name`

## 7. 调用日志月表维护规则

调用日志按月分表，命名固定为：

- `fx_api_call_log_yyyyMM`

维护规则：

1. 服务启动时自动确保当月表和下月表存在。
2. 每天定时检查当月表。
3. 每月最后一天提前创建下月表。
4. 写入日志前按 `callTime` 再兜底创建。
5. 查询时自动跳过不存在的历史月份表，避免缺表报错。

## 8. 排障建议

出现问题时按以下顺序排查：

1. 接口配置是否启用且方向正确。
2. 出站目标配置是否正确。
3. 参数结构和字段映射是否完整。
4. 入站处理器 Bean 是否存在。
5. 异步任务结果表是否有结果。
6. 调用日志中的原始参数、组装参数、错误信息是否完整。

## 9. 参数结构与字段级映射规范

接口平台不能假设第三方字段名与 Forgex 字段名一致，参数配置必须按双方真实接口结构维护到字段级别。

配置原则：

1. 请求字段、响应字段都必须从双方真实 JSON 或 Java 实体导入，不允许只配置 `users` 这类整包数组后直接透传。
2. 字段映射必须配置到叶子字段，例如 `root.users.account -> root.commonUsers.code`。
3. 对方集合名称不需要与 Forgex 一致，例如第三方可以叫 `commonUsers`，账号可以叫 `code`，平台通过映射关系完成转换。
4. 数组对象字段按同一数组节点下的叶子字段逐项映射，平台会按下标合并为第三方要求的数组结构。
5. 来源类型和目标类型必须能从参数树中查到；如果映射行类型为空，优先检查字段路径是否真实存在于请求/响应字段树。
6. 出站接口请求映射使用 `OUTBOUND`，用于把内部业务参数组装成第三方请求。
7. 出站接口响应回写映射使用 `INBOUND`，用于把第三方响应转换回内部业务结构。
8. 入站接口映射使用 `INBOUND`，用于把第三方主动推送请求转换成内部处理器参数。

字段级示例：

```text
Forgex 源字段                第三方目标字段
root.tenantId         ->     root.companyId
root.users.account    ->     root.commonUsers.code
root.users.username   ->     root.commonUsers.name
root.users.email      ->     root.commonUsers.mail
root.users.phone      ->     root.commonUsers.mobile
root.users.status     ->     root.commonUsers.enable
```

生成的第三方请求结构示例：

```json
{
  "companyId": 1,
  "commonUsers": [
    {
      "code": "admin",
      "name": "管理员",
      "mail": "admin@example.com",
      "mobile": "13800000000",
      "enable": true
    }
  ]
}
```

SQL 脚本注意事项：

- 包含中文的配置脚本必须保存为 UTF-8，并在脚本开头写 `SET NAMES utf8mb4;`。
- Windows PowerShell 不要把大量中文 SQL 直接拼到 `mysql --execute` 一行里，容易出现 `????` 数据。
- 不要通过 PowerShell 管道把中文 SQL 传给 `mysql`，例如 `Get-Content xxx.sql | mysql ...`，也可能出现 `????` 数据。
- 推荐执行方式：先写入 UTF-8 `.sql` 文件，再使用 `mysql --default-character-set=utf8mb4 --execute="source D:/path/file.sql"`。

## 10. 错误返回与国际化配置

接口平台后端返回错误时必须走统一国际化链路，不能直接写死中文或返回抽象异常。

后端开发约定：

1. 业务错误优先抛出 `I18nBusinessException(StatusCode.BUSINESS_ERROR, IntegrationPromptEnum.xxx, args...)`。
2. Controller 直接返回失败时使用 `R.fail(IntegrationPromptEnum.xxx)` 或 `R.failWithArgs(...)`。
3. 不允许在接口平台新增 `result.setMessage("中文文案")`、`R.fail("中文文案")`、`RuntimeException("中文文案")` 这类硬编码返回。
4. 每个 `IntegrationPromptEnum` 提示码都必须在 `forgex_common.fx_i18n_message` 中配置 `module='integration'` 的文案。
5. 集成服务运行环境必须配置 `common` 动态数据源，否则无法从 `forgex_common.fx_i18n_message` 读取国际化文案。
6. 写操作成功也必须返回带提示码的 `R.ok(IntegrationPromptEnum.xxx_SUCCESS)`，不能只返回 `R.ok()`，否则前端无法展示成功提示。

本地错误文案初始化脚本：

```text
Forgex_Doc/数据库/脚本与修复/20260511_integration_i18n_error_messages.sql
```

推荐执行方式：

```bash
mysql --host=127.0.0.1 --user=root --password=123456 --default-character-set=utf8mb4 --execute="source D:/mine_product/forgex/Forgex_Doc/数据库/脚本与修复/20260511_integration_i18n_error_messages.sql"
```

验证方式：

```sql
USE forgex_common;
SELECT prompt_code,
       JSON_UNQUOTE(JSON_EXTRACT(text_i18n_json, '$."zh-CN"')) AS zh_cn
FROM fx_i18n_message
WHERE module = 'integration'
  AND prompt_code IN (
    'API_AUTH_FAILED',
    'API_TARGET_ROUTE_ONLY_PATH',
    'API_OUTBOUND_TARGET_REQUIRED',
    'API_THIRD_SYSTEM_IP_REQUIRED',
    'THIRD_AUTH_TOKEN_GENERATED',
    'CALL_LOG_NOT_FOUND'
  );
```

## 12. 用户管理本地 ERP 联调说明

首次验证 Forgex 接口平台能力时，用户管理建议优先联调以下两条接口：

- `sys_user_sync`：用户同步第三方
- `sys_user_pull`：用户拉取第三方
- `sys_user_third_party_inbound`：第三方推送用户

当前本地测试约定如下：

- 第三方系统名称：`本地ERP测试系统`
- 第三方系统地址：`192.168.3.7:18080`
- 同步路由：`/api/users/third-party/sync`
- 拉取路由：`/api/users/third-party/pull`
- 第三方用户集合：`commonUsers`
- 第三方账号字段：`code`
- 第三方姓名字段：`name`

说明：

- 目标地址只保存端口后的接口路由，IP 和端口来自“第三方系统管理”的 `ip_address`。
- 用户同步第三方必须配置 `root.users.* -> root.commonUsers.*` 的字段级映射。
- 用户拉取第三方必须配置 `root.commonUsers.* -> root.users.*` 的字段级映射。
- 第三方推送用户也必须配置 `root.commonUsers.* -> root.users.*` 的字段级映射。
- 不允许由本地 ERP 适配 Forgex 的 `users/account` 原结构，否则无法验证接口平台字段映射能力。

用户拉取第三方需要特别注意两段映射：

1. `OUTBOUND`：Forgex 拉取条件转换为 ERP 请求体，例如 `root.tenantId -> root.companyId`、`root.includeDisabled -> root.includeStop`。
2. `INBOUND`：ERP 响应转换回 Forgex 用户结构，例如 `root.commonUsers.code -> root.users.account`、`root.commonUsers.name -> root.users.username`。

因此 `sys_user_pull` 的参数树里必须同时能看到 Forgex 拉取条件、ERP 拉取请求字段、ERP 响应字段和 Forgex 用户目标字段。保存映射前，双方字段路径都要能在请求或响应参数树中查到字段类型。
## 13. 授权配置补充说明

第三方系统管理中的“授权配置”用于控制外部系统调用 Forgex 入站接口时的身份校验。

- `TOKEN`：调用方必须在公共调用请求体中传 `token` 或 `authToken`，平台校验 Token 是否存在、启用、未过期。
- `WHITELIST`：调用方 IP 命中白名单时直接放行，不要求传 Token。
- `TOKEN_WHITELIST`：白名单 IP 免 Token；非白名单 IP 必须传有效 Token。

Token 有效期支持以下方式：

- 按天、按月、按年：填写有效期数值，平台从生成时间开始计算过期时间。
- 指定时间：直接选择明确的过期时间。
- 无期限：`token_expire_time` 为空，Token 不因时间过期。

入站接口如果需要绑定指定第三方系统授权，需要在 `fx_api_config.auth_config` 中维护：

```json
{"thirdSystemId": 2045037285200052226}
```

例如用户入站测试接口 `sys_user_third_party_inbound` 绑定到本地 ERP 测试系统后，调用时如果来源 IP 命中该系统白名单，不需要传 Token；否则必须传该系统授权配置生成的 Token。
