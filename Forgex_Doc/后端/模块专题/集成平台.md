# 集成平台

> 分类：后端 / 模块专题
> 版本：V0.8.5
> 说明：本文为当前接口平台正式说明，已覆盖 2026-05 调用日志专项修复内容。

## 1. 模块定位

集成平台负责两类能力：

1. 内部服务调用外部接口。
2. 外部系统调用内部业务接口。

平台统一提供接口配置、参数结构配置、字段映射、鉴权、同步/异步执行、调用日志和任务结果查询能力。

## 2. 当前标准入口

### 2.1 内部调用外部

内部统一通过 `IntegrationFacade` 调用：

```java
IntegrationExecuteResult result = integrationFacade.invoke("sys_user_sync", requestEntity);
```

说明：

- 只传 `apiCode` 和业务实体。
- 平台自动加载接口定义、组装请求参数、调用第三方系统、记录日志。

### 2.2 外部调用内部

外部统一通过 HTTP 入口调用：

- `POST /api/integration/public/invoke`
- `GET /api/integration/public/task/{taskId}`

请求体中只有 `jiekou_code` 是平台保留字段，其余字段全部进入业务 `payload`。

示例：

```json
{
  "jiekou_code": "sys_user_third_party_inbound",
  "token": "abc123",
  "tenantId": 10001,
  "users": [
    {
      "userCode": "U001",
      "userName": "Alice"
    }
  ]
}
```

## 3. 核心配置模型

### 3.1 接口配置 `fx_api_config`

用于定义接口基础信息：

- `api_code`：接口编码，唯一标识。
- `direction`：`INBOUND` 或 `OUTBOUND`。
- `invoke_mode`：`SYNC` 或 `ASYNC`。
- `target_url`：出站默认目标地址。
- `processor_bean`：入站处理器 Bean。
- `content_type`、`http_method`、`timeout_ms`、`retry_count` 等执行参数。

### 3.2 出站目标 `fx_api_outbound_target`

用于给一个出站接口配置一个或多个第三方目标系统。

关键字段：

- `api_config_id`
- `target_code`
- `target_name`
- `target_url`
- `invoke_mode`
- `order_num`

### 3.3 参数结构 `fx_api_param_config`

用于定义请求/响应参数树。

关键字段：

- `parent_id`：父节点 ID。
- `direction`：`REQUEST` 或 `RESPONSE`。
- `node_type`：`OBJECT`、`ARRAY`、`FIELD`。
- `field_name`：字段名。
- `field_path`：完整路径。

推荐约定：

- 根节点通常为 `root`，类型为 `OBJECT`。
- 对象节点配置为 `OBJECT`。
- 数组或集合节点配置为 `ARRAY`。
- 叶子字段配置为 `FIELD`。

集合对象数组示例：

```text
root                    OBJECT
root.users              ARRAY
root.users.userCode     FIELD
root.users.userName     FIELD
root.users.phone        FIELD
```

### 3.4 字段映射 `fx_api_param_mapping`

用于定义双方字段如何对接。

关键字段：

- `source_field_path`
- `target_field_path`
- `target_scope`：`BODY`、`QUERY`、`HEADER`、`PATH`
- `value_type`：`SOURCE`、`DEFAULT`、`CONSTANT`
- `transform_rule`

示例：

```text
tenantId -> tenant_id          BODY   SOURCE
users -> data.users            BODY   SOURCE
token -> Authorization         HEADER SOURCE
orderId -> orderId             PATH   SOURCE
pageNo -> page                 QUERY  DEFAULT
```

## 4. 执行与日志

### 4.1 出站执行

执行流程：

1. 按 `apiCode + OUTBOUND + tenantId` 加载接口定义快照。
2. 将业务实体转换为 `Map`。
3. 根据参数映射组装 `body/query/header/pathVariables`。
4. 调用第三方 HTTP 接口。
5. 记录调用日志。

### 4.2 入站执行

执行流程：

1. 通过 `jiekou_code` 加载 `INBOUND` 接口定义。
2. 校验 token。
3. 将外部 payload 组装为业务参数。
4. 同步执行处理器或提交异步任务。
5. 记录调用日志。

### 4.3 调用日志

调用日志按月分表，命名固定为：

- `fx_api_call_log_yyyyMM`

日志保留的关键内容：

- `raw_request_data`：入口原始参数。
- `request_data`：请求快照。
- `assembled_request_data`：组装后的完整请求定义。
- `response_data`：第三方响应或处理结果。
- `response_code`
- `result_type`
- `error_message`
- `trace_id`
- `task_id`
- `outbound_target_id`
- `target_system_code`
- `target_system_name`

出站调用时，`assembled_request_data` 记录完整 `OutboundRequestDefinition`，即：

- `body`
- `query`
- `headers`
- `pathVariables`
- `targetUrl`

## 5. 2026-05 调用日志专项修复

本次已修复以下问题：

1. 月表自动创建。
   平台会在启动时创建当月和下月表，每天定时检查当月表，并在月末提前创建下月表；每次写日志前再做一次兜底建表。
2. 缺表不再影响查询。
   分页、列表、统计、成功率查询会先过滤真实存在的月份表，缺失历史月表时直接跳过。
3. 用户页面调用第三方接口补齐日志。
   通过 `IntegrationFacade -> ApiGatewayServiceImpl` 的调用链，会记录成功、失败、异步受理、鉴权失败等场景。
4. 日志内容更完整。
   不仅记录原始参数，还记录组装后参数和返回结果。

## 6. 排障建议

调用记录异常时按以下顺序排查：

1. 确认调用是否经过集成平台标准入口。
2. 确认目标月份表是否存在，例如 `fx_api_call_log_202605`。
3. 检查 `raw_request_data`、`assembled_request_data`、`response_data`。
4. 检查 `trace_id`、`task_id` 是否可串联执行链路。
5. 检查接口配置、目标系统配置、参数结构配置、字段映射配置。
