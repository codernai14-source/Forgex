# 报表中心使用方式

> 分类：后端 / 模块专题
> 版本：**V1.0.0**

## 源码与接入方式

- 后端：Forgex_MOM/Forgex_Backend/Forgex_Report/src/main/java/com/forgex/report/controller/ReportTemplateController.java、ReportDatasourceController.java、ReportCategoryController.java。
- 前端：Forgex_MOM/Forgex_Fronted/src/api/report/index.ts 和 views/report/components/ReportDesigner.vue、ReportPreview.vue。
- 引擎：UReport2 使用 UREPORT，JimuReport 使用 JIMU。

后端模板按编码查询的真实路径是 GET /report/template/by-code/{code}?engineType=UREPORT；按 ID 查询是 GET /report/template/{id}。当前前端 getByCode() 实现拼接的是 /report/template/{code}，会把编码当作 Long ID 解析，这是已知对接缺口。

## 基础调用

```ts
import http from '@/api/http'
import { getPreviewUrl } from '@/api/report'

// 临时按后端真实路径查询编码
const template = await http.get('/report/template/by-code/sales-summary', { params: { engineType: 'UREPORT' } })
const previewUrl = getPreviewUrl('sales-summary', 'UREPORT', { tenantId: '1' })
```

修复前端 API 后，可把第一行替换为 getByCode('sales-summary', 'UREPORT')；修复内容应同步更新 report/index.ts 和对应测试。

## 管理顺序和高阶场景

1. 通过 /report/category/save 创建分类。
2. 通过 /report/datasource/save 保存数据源，使用 /report/datasource/test 测试未保存配置或 /report/datasource/test/{id} 测试已保存数据源。
3. 通过 /report/template/save 保存模板元数据，再由设计器调用 /report/template/update-content 保存内容。
4. 按模板 engineType 选择 getDesignerUrl 或 getPreviewUrl；UREPORT 地址使用 /ureport，JIMU 地址使用 /jimureport。

参数会追加到预览 URL，编码由 getPreviewUrl 负责；不要在页面手工拼接未编码的查询参数。

## 推荐用法与排错

- 模板 code 和 engineType 一起作为稳定标识，避免同编码跨引擎误取。
- 设计器打不开：先检查 report:template:design 权限、引擎配置和生成的 URL。
- 通过编码查询 404/400：确认使用 /by-code/{code}；当前 getByCode 前端实现仍需修复。
- 报表无数据：先调用数据源 test，再检查 SQL、租户权限和参数绑定。
- 导入导出失败：检查 report:template:import/export 权限及服务器文件路径；接口返回的是 R，不是前端文件流。
- 数据源测试成功不代表报表查询成功，真实引擎和 SQL 仍需目标环境联调。
