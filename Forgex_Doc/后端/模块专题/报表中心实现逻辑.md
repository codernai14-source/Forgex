# 报表中心实现逻辑

> 分类：后端 / 模块专题
> 版本：**V1.0.0**

## 源码位置

- 分类：Forgex_MOM/Forgex_Backend/Forgex_Report/src/main/java/com/forgex/report/controller/ReportCategoryController.java
- 数据源：同目录 ReportDatasourceController.java、ReportDatasourceServiceImpl.java
- 模板：同目录 ReportTemplateController.java、ReportTemplateServiceImpl.java
- 引擎配置：同目录 config/UreportConfig.java、JimuConfig.java、ReportConfig.java
- 前端 API：Forgex_MOM/Forgex_Fronted/src/api/report.ts

## 接口和流程

分类、数据源和模板 Controller 的内部前缀分别为 /category、/datasource、/template。分类和数据源查询使用 GET /page、/list、/{id}，保存使用 POST /save；数据源另有 GET /by-code/{code}、POST /test。模板提供 GET /page、/{id}、/by-code/{code}，POST /save、/update-content、/export/{id}、/import。

    创建分类 -> 配置数据源 -> 测试连接
           -> 保存模板元数据和内容
           -> 按 code 查询模板
           -> 交给 UReport2 或 JimuReport 设计/预览/导出

ReportTemplateServiceImpl 负责租户范围、模板元数据和内容持久化；具体设计器页面和引擎 URL 由配置类及前端 getPreviewUrl 等函数组合。当前源码不能从模板管理 Controller 推导出统一的设计器认证协议，联调时必须查看实际配置。

## 二次开发和现状

新增引擎需要扩展 ReportEngineType、配置类、模板 URL 解析、导入导出适配和前端选择器。数据源测试只验证连接，不代表报表 SQL 有权限或返回正确数据。报表接口的权限、租户过滤和真实引擎可用性需要在目标环境验收；文档不能把双引擎预览描述为已经统一实现。
