# 标签模板实现逻辑

> 分类：后端 / 模块专题

本文说明标签模板重构的后端实现思路，核心是把原先单表模板内容升级为“类型、字段、模板主表、模板详情”四表模型，并提供统一打印渲染能力。

## 模型划分

### 标签类型表

用于维护标签分类。

核心字段：

- `typeCode`
- `typeName`
- `isEnabled`

### 标签字段表

用于维护模板可绑定的业务字段。

核心字段：

- `fieldCode`
- `fieldName`
- `fieldType`
- `moduleId`
- `isEnabled`

### 标签模板主表

用于维护模板基础信息，不再承载完整设计 JSON。

核心字段：

- `typeId`
- `templateCode`
- `templateName`
- `version`
- `isEnabled`
- `paperWidth`
- `paperHeight`

### 标签模板详情表

用于维护拖拽设计器生成的组件数据。

核心字段：

- `templateId`
- `componentType`
- `positionX`
- `positionY`
- `componentWidth`
- `componentHeight`
- `componentContent`
- `styleJson`

## 后端分层

标签模块位于 `Forgex_Basic` 下的 `com.forgex.basic.label` 包，按常规四层结构拆分：

- `controller`
- `service`
- `domain`
- `mapper`

已提供类型、字段、模板、打印相关的 Entity、DTO、Param、VO、Mapper 和 Service。

## 设计器保存

设计器页面通过模板详情接口加载组件列表，保存时将组件数据统一提交到设计保存接口。

保存内容包含：

- 组件类型
- 坐标与尺寸
- 固定值或字段绑定值
- 字体、字号、对齐、粗细等样式 JSON

位置与尺寸统一按毫米存储，前端画布按比例换算为像素展示。

## 打印渲染

打印渲染链路的核心目标是把业务实体转换为可直接渲染的数据结构。

处理步骤：

1. 按模板编码读取模板主表
2. 读取模板组件详情
3. 将传入实体或 `Map` 转换为字段字典
4. 遍历组件详情，若组件为字段绑定模式，则按字段名取值
5. 命中字段则替换组件内容
6. 未命中字段则保留原始固定值
7. 返回前端渲染所需的完整模板 VO

## 字段匹配规则

字段匹配以“字段名完全一致”为准。

例如：

- 模板组件绑定 `matName`
- 传入实体包含 `matName = 测试物料`
- 渲染结果中该组件内容变为 `测试物料`

如果字段缺失，后端不会替换为异常占位，前端按返回值渲染即可。

## 扩展说明

1. 模板编码在同一租户内应保持唯一。
2. 字段编码在同一租户和模块下应保持唯一。
3. 设计器组件新增类型时，需要同步前端组件库、后端枚举、VO 和保存逻辑。
4. 打印链路与模板设计链路解耦，前端不再自行解析业务实体。
