# 基础数据与物料实现逻辑

> 分类：后端 / 模块专题
> 版本：**V0.6.5**
> 更新时间：**2026-04-17**

本文档说明 `Forgex_Basic` 模块中基础业务探针和物料管理的实现结构。

## 模块定位

`Forgex_Basic` 承担基础业务扩展位，当前重点是物料管理与模块探针。

| 入口 | 作用 |
|---|---|
| `BasicModuleController` | 模块健康探针 |
| `BasicMaterialController` | 物料管理 |

## 生产组织主数据链路

车间、人员、班次、班组四类主数据均落在 `Forgex_Basic`，业务表默认位于 `forgex_admin`：

| 表 | 说明 |
|---|---|
| `basic_workshop` | 车间主数据，维护车间编码、名称、所属工厂、启用状态 |
| `basic_employee` | 人员主数据，维护工号、姓名、联系方式、部门、岗位、启用状态 |
| `basic_shift` | 班次主表，维护班次编码、名称、启用状态 |
| `basic_shift_period` | 班次时段子表，维护 `WORK` / `REST` 时段和开始、结束时间 |
| `basic_team` | 班组主表，维护班组编码、名称、负责人、当前班次、所属车间 |
| `basic_team_employee` | 班组人员子表，按班组维护人员集合 |

后端实现位置：

```text
Forgex_MOM/Forgex_Backend/Forgex_Basic/src/main/java/com/forgex/basic/workshop
Forgex_MOM/Forgex_Backend/Forgex_Basic/src/main/java/com/forgex/basic/employee
Forgex_MOM/Forgex_Backend/Forgex_Basic/src/main/java/com/forgex/basic/shift
Forgex_MOM/Forgex_Backend/Forgex_Basic/src/main/java/com/forgex/basic/team
```

各主数据均提供 `page`、`list`、`detail`、`create`、`update`、`delete`、`batchDelete` 接口。编码唯一性在服务层按当前租户和未删除数据校验：车间编码、工号、班次编码、班组编码均不可重复。删除保护同样在服务层完成：人员被班组人员引用、车间被班组引用、班次被班组当前班次引用时禁止删除。

班次保存以 `ShiftDTO.periodList` 携带时段子表，`ShiftServiceImpl` 在事务内保存主表并重建时段明细；结束时间小于等于开始时间时不落额外偏移字段，由业务展示侧按跨天理解。班组保存以 `TeamDTO.employeeList` 携带班组人员，`TeamServiceImpl` 在事务内保存主表并重建人员明细，同时校验人员不可重复。

人员同步用户链路：

```text
POST /basic/employee/sync-user
  -> EmployeeServiceImpl.syncUser
  -> 按 basic_employee.employee_no 查询 sys_user.account
  -> 不存在则使用系统默认密码策略创建用户
  -> 存在则更新姓名、手机、邮箱、性别、头像、入职日期、部门、岗位、状态
  -> 写入 sys_user.employee_id = basic_employee.id
  -> 写入 sys_user_tenant 租户绑定
```

该链路不绑定角色，适用于“人员先建档，再按工号开通登录账号”的场景。批量同步接口为 `/basic/employee/batch-sync-user`，单条失败会记录失败工号并继续处理后续人员。

人员第三方同步复用接口平台：

| 入口 | 说明 |
|---|---|
| `EmployeeServiceImpl.syncToThirdParty` | 默认接口编码 `basic_employee_sync`，导出人员并通过接口平台出站同步 |
| `EmployeeServiceImpl.pullFromThirdParty` | 默认接口编码 `basic_employee_pull`，从第三方拉取后回写人员主数据 |
| `InternalEmployeeIntegrationController` | 接口平台内部编排控制器，负责导出人员、调用平台配置和回写 |
| `EmployeeThirdPartyInboundInterpreter` | 接收第三方主动推送的人员数据并调用 Basic 内部接口写入 |
| `IntegrationEmployeeSyncFeignClient` | Integration 调用 Basic 内部人员同步接口的 Feign 合约 |

表结构、菜单权限、公共表格配置和接口平台默认配置由 `Forgex_Doc/数据库/脚本与修复/20260517_basic_employee_shift_team.sql` 补齐。公共表格配置放在 `forgex_common`，接口平台默认配置放在 `forgex_integration`，业务表和菜单权限放在 `forgex_admin`。

## 物料链路

```text
物料新增 / 更新
  -> 编码规则生成物料编码
  -> 字典解析类型、状态
  -> 多租户入库
  -> 可联动导入导出
```

物料分页查询由 `MaterialPageParam` 接收条件，`MaterialServiceImpl` 使用 MyBatis-Plus `LambdaQueryWrapper` 组合筛选。当前支持按物料编码、物料名称、物料类型、物料分类、计量单位、品牌、状态、审批状态查询；其中编码、名称、分类、计量单位、品牌使用模糊匹配，类型、状态和审批状态使用精确匹配。

物料详情由 `/basic/material/detail` 返回 `MaterialDetailResponse`，其中 `baseInfo` 承载主表字段，`extendList` 保留 `basic_material_extend` 中按模块保存的原始附属值，`extendViewList` 由后端按 `basic_material_extend_schema` 的字段结构合并 `extend_json` 后生成，前端直接渲染“模块 + 字段表格 + 字段详情”的可视化页表。新增和更新接口支持 `MaterialDTO.extendValueList` 结构化附属值，服务层按字段配置校验必填和类型后序列化回现有 `extend_json`；未配置的历史 JSON key 会在详情中进入“未配置字段”只读区，并在更新时保留，避免旧数据丢失。

物料附属字段配置由 `/material/extend-schema/*` 提供接口，权限建议使用 `basic:material:extendConfig:*`。配置范围为 `tenantId + module + materialType`，字段行继续落在 `basic_material_extend_config`，每次新增、修改、删除、启停和排序字段后同步刷新 `basic_material_extend_schema.schema_json`，用于支撑物料弹窗动态渲染字段结构。

物料公共导入和第三方同步复用同一套聚合模型：

```text
前端 CommonImportDialog / 第三方拉取
  -> MaterialAggregateDTO
  -> MaterialServiceImpl.validateAggregate
  -> 按 tenantId + materialCode 查找已有物料
  -> ADD / UPDATE / COVER 或第三方同步模式写入主表
  -> 重建 extendList 附属信息，兼容 schema 字段 key 映射
```

相关实现入口：

| 入口 | 说明 |
|---|---|
| `BasicMaterialImportHandler` | 公共导入处理器 Bean，配置名为 `basicMaterialImportHandler` |
| `MaterialServiceImpl.executeCommonImport` | 解析 `basic_material` 导入数据，支持 `ADD`、`UPDATE`、`COVER` |
| `MaterialServiceImpl.syncToThirdParty` | 调用接口平台默认编码 `basic_material_sync` 出站同步 |
| `MaterialServiceImpl.pullFromThirdParty` | 调用接口平台默认编码 `basic_material_pull` 拉取并写入 |
| `InternalMaterialIntegrationController` | 接口平台内部编排控制器，负责导出物料、调用平台配置、回写基础数据 |
| `IntegrationMaterialSyncFeignClient` | 接口平台调用 Basic 模块的内部 Feign 合约 |

公共导入模板配置、附属字段结构表、按钮权限和默认接口编码由 `Forgex_Doc/数据库/脚本与修复/20260512_material_import_sync_upgrade.sql` 补齐。该脚本会创建 `basic_material_extend_schema`、为 `basic_material_extend_config` 补齐 `material_type`，并写入 `fx_excel_import_config`、`fx_excel_import_config_item`、`sys_menu` / `sys_role_menu` 和接口平台默认 API 配置。

## 币种与汇率链路

币种与汇率能力位于 `Forgex_Basic` 的 `com.forgex.basic.currency` 包，默认业务表存放在 `forgex_admin`：

| 表 | 说明 |
|---|---|
| `mdm_currency` | 币种主数据，维护 ISO 4217 编码、名称、符号、小数位、本位币和启用状态 |
| `mdm_exchange_rate_type` | 汇率类型，维护汇率类型编码、名称、业务场景、默认标记和启用状态 |
| `mdm_currency_exchange_rate` | 汇率明细，维护源币种、目标币种、汇率类型、生效日期、失效日期、审批状态和组织维度 |
| `mdm_exchange_rate_log` | 汇率操作日志，记录新增、修改、审批等操作内容 |

新增币种、汇率类型、汇率明细时，服务层按当前 `TenantContext` 写入 `tenant_id`，避免数据写到公共租户后被 MyBatis-Plus 租户拦截器过滤导致“保存成功但列表不可见”。更新时保留已有记录租户，避免跨租户覆盖。已有数据库若缺少币种表或默认数据，执行 `Forgex_Doc/数据库/脚本与修复/20260517_basic_currency_table_fix.sql`，该脚本会幂等创建四张表并为公共租户与当前默认租户写入 CNY、BOOKING 初始数据。

## 包装规格与三槽关联

包装规格主数据复用 `basic_packaging_type`，当前字段语义已调整为包装规格编码、名称、类型、长宽高、尺寸单位、容积、容积单位、重量、重量单位、状态、排序和备注。分页接口 `/basic/packaging/page` 由 `BasicPackagingTypeController` 暴露，列表查询按 `packagingCode`、`packagingName`、`packagingSpecType` 和 `status` 组合筛选，并在服务层联查 `basic_unit` 回填 `sizeUnitName`、`volumeUnitName`、`weightUnitName` 以及尺寸、容积、重量展示字段。

包装规格类型走字典 `packaging_spec_type`，字典值固定为 `BOX`、`BUCKET`、`ROLL`、`CASE`、`BAG`，分别对应箱、桶、卷、盒、袋。服务层创建和更新时会校验字典可用性，避免前端写入非法类型值。

物料与包装规格通过 `basic_material_packaging_relation` 维护固定三槽位：`SMALL`、`MEDIUM`、`LARGE`。包装规格页和物料页都复用同一套关联接口：

| 接口 | 说明 |
|---|---|
| `/basic/packaging/relation/listByMaterial` | 按物料查询三槽绑定 |
| `/basic/packaging/relation/listByPackaging` | 按包装规格查询关联物料 |
| `/basic/packaging/relation/saveByMaterial` | 一次性保存物料三槽绑定 |
| `/basic/packaging/relation/saveSlot` | 保存单个槽位绑定 |
| `/basic/packaging/relation/delete` | 删除关联记录 |

删除包装规格或物料时，服务层会同步软删对应关联记录，查询阶段只返回未删除的包装规格和关联数据。
包装规格批量删除复用 `/basic/packaging/batchDelete`，控制层接收 `ids` 集合后调用 `IBasicPackagingTypeService.batchDeletePackagingTypes`。前端列表通过 `FxDynamicTable.rowSelection` 维护选中行，删除成功后清空选择并刷新当前表格。

## 供应商主数据链路

供应商主数据位于 `Forgex_Basic` 模块，前端页面位于：

```text
Forgex_MOM/Forgex_Fronted/src/views/basic/supplier/index.vue
```

核心实现分层：

| 层级 | 说明 |
|---|---|
| `SupplierController` | 暴露分页、详情、新增、更新、删除、导入导出、生成租户、发起审查等接口 |
| `ISupplierService` / `SupplierServiceImpl` | 负责供应商主表、详情、联系人、资质、租户生成和工作流联动 |
| `BasicSupplier` | 供应商主表实体 |
| `BasicSupplierDetail` | 供应商扩展详情 |
| `BasicSupplierContact` | 供应商联系人 |
| `BasicSupplierQualification` | 供应商资质 |

新增 / 更新链路：

```text
前端供应商弹窗
  -> 校验供应商编码或自动生成配置
  -> 调用 supplierApi.create / supplierApi.update
  -> 后端保存主表、详情、联系人、资质
  -> 刷新 FxDynamicTable 列表
```

供应商新增弹窗使用公共 `BaseFormDialog`，并在业务调用处开启 `maskClosable`。该行为只作用于供应商页面，不改变公共弹窗默认的复杂表单保护策略。

供应商生成租户链路：

```text
POST /basic/supplier/generate-tenant
  -> SupplierServiceImpl.generateTenant
  -> SysTenantFeignClient.create 创建 SUPPLIER_TENANT
  -> TenantInitServiceImpl.initTenant 异步初始化
  -> 写入管理员账号、sys_user_tenant 租户绑定、管理员角色和菜单授权
  -> 回写 basic_supplier.related_tenant_code
```

供应商租户管理员账号使用租户编码而不是供应商名称生成，规则为 `admin_{tenantCode 去除非字母数字并转小写}_{tenantId 后4位}`，避免中文供应商名称导致账号不可预期。认证服务登录时会先按 `sys_user.account` 校验密码，再读取 `sys_user_tenant` 返回可选租户，因此初始化必须同时创建账号和租户绑定。历史环境如存在供应商租户但缺少账号或绑定，可执行 `Forgex_Doc/数据库/脚本与修复/20260512_supplier_tenant_login_fix.sql` 补齐。

## 计量单位链路

计量单位采用“类型树 + 单位主数据 + 换算关系”三表模型：

| 表 | 说明 |
|---|---|
| `basic_unit_type` | 计量单位类型树，维护类型编码、类型名称、父 ID 和层级路径 |
| `basic_unit` | 计量单位主数据，按类型维护单位编码、单位名称和备注 |
| `basic_unit_conversion` | 计量单位换算关系，表示 `1 源单位 = conversion_value 目标单位` |

计量单位三张业务表随 `Forgex_Basic` 默认主数据源存放在 `forgex_admin`；公共表格配置、国际化提示等公共配置仍存放在 `forgex_common`。旧版单表 `basic_unit` 升级时会按租户创建 `DEFAULT/默认类型` 并回填 `unit_type_id`，避免列表接口查询新字段时报错。

后端实现位置：

```text
Forgex_MOM/Forgex_Backend/Forgex_Basic/src/main/java/com/forgex/basic/material/controller/BasicUnitController.java
Forgex_MOM/Forgex_Backend/Forgex_Basic/src/main/java/com/forgex/basic/material/service/impl/BasicUnitServiceImpl.java
Forgex_MOM/Forgex_Backend/Forgex_Common/src/main/java/com/forgex/common/api/dto/UnitConvertRequestDTO.java
Forgex_MOM/Forgex_Backend/Forgex_Common/src/main/java/com/forgex/common/api/feign/BasicUnitConversionFeignClient.java
```

删除保护规则在服务层统一执行：类型下存在子类型或单位时禁止删除；单位存在源或目标换算关系时禁止删除。换算配置保存按源单位执行全量替换：前端提交的多行关系会保留或更新，未提交的源单位旧关系会被删除。
计量单位批量删除复用 `/basic/unit/batchDelete`，控制层接收 `ids` 集合后调用 `IBasicUnitService.batchDeleteUnits`。前端只提供批量删除，不提供批量修改；当前 `basic_unit` 主数据模型没有状态字段，启停类批量操作不属于本轮能力。

计量单位分页查询由 `UnitPageParam` 接收条件，`BasicUnitServiceImpl` 使用 `unitTypeId`、单位编码、单位名称和单位类型名称组合筛选。单位类型名称会先查询当前租户下匹配的 `basic_unit_type`，再按匹配到的类型 ID 过滤 `basic_unit`；如果没有匹配类型，列表返回空结果。

公共换算方法使用严格模式。调用方传入实体数据、目标单位编码、实体内单位字段名、单位字段类型 `ID/CODE` 和待换算数字字段名数组。服务会查询源单位、目标单位与直接关系；缺少直接关系时允许使用反向关系并执行除法。同单位直接返回原值。单位、字段、关系缺失或字段非数字时抛业务异常，计算使用 `BigDecimal`，不做默认四舍五入。

## 2026-06-19 客户与首页组件实现补充

- 基础信息模块默认首页组件由 PersonalHomepageConfig.defaults("basic") 和前端 personalHomepage.ts 共同维护，当前默认组件为 supplierInfo、customerInfo、workCalendarInfo。历史布局中的 encodeRuleInfo 渲染时会被过滤，编码规则管理菜单和后端能力不删除。

- 客户导入导出以当前客户聚合模型为准，主 Sheet 覆盖客户主表常用字段，导入后走客户聚合 upsert，避免新增数据库字段。
