# 基础数据与物料实现逻辑

> 分类：后端 / 模块专题
> 版本：**V0.6.5**
> 更新时间：**2026-04-17**

本文档说明 `Forgex_Basic` 模块中基础业务探针和物料管理的实现结构。

## 模块定位

`Forgex_Basic` 承担基础业务扩展位，当前重点是物料管理与模块探针。

## 核心入口

| 入口 | 作用 |
|---|---|
| `BasicModuleController` | 模块健康探针 |
| `BasicMaterialController` | 物料管理 |
| `SupplierController` | 供应商主数据管理 |
| `BasicUnitController` | 计量单位类型、单位主数据与换算关系 |
| `BasicUnitInternalController` | 计量单位公共换算内部接口 |

## 物料链路

```text
物料新增 / 更新
  -> 编码规则生成物料编码
  -> 字典解析类型、状态
  -> 多租户入库
  -> 可联动导入导出
```

物料分页查询由 `MaterialPageParam` 接收条件，`MaterialServiceImpl` 使用 MyBatis-Plus `LambdaQueryWrapper` 组合筛选。当前支持按物料编码、物料名称、物料类型、物料分类、计量单位、品牌、状态、审批状态查询；其中编码、名称、分类、计量单位、品牌使用模糊匹配，类型、状态和审批状态使用精确匹配。

物料详情由 `/basic/material/detail` 返回 `MaterialDetailResponse`，其中 `baseInfo` 承载主表字段，`extendList` 保留 `basic_material_extend` 中按模块保存的原始附属值，`extendViewList` 由后端按 `basic_material_extend_schema` 的字段结构合并 `extend_json` 后生成，前端直接渲染“模块 + 字段表格 + 字段详情”的可视化页表。新增和更新接口支持 `MaterialDTO.extendValueList` 结构化附属值，服务层按字段配置校验必填和类型后序列化回现有 `extend_json`；未配置的历史 JSON key 会在详情中进入“未配置字段”只读区，并在更新时保留，避免旧数据丢失。

物料附属字段配置由 `/material/extend-schema/*` 提供接口，权限建议使用 `basic:material:extendConfig:*`。配置范围为 `tenantId + module + materialType`，字段行继续落在 `basic_material_extend_config`，每次新增、修改、删除、启停和排序字段后同步刷新 `basic_material_extend_schema.schema_json`，用于支撑物料弹窗动态渲染字段结构。

物料公共导入和第三方同步复用同一套聚合模型：

```text
前端 CommonImportDialog / 第三方拉取
  -> MaterialAggregateDTO
  -> MaterialServiceImpl.validateAggregate
  -> 按 tenantId + materialCode 查找已有物料
  -> ADD / UPDATE / COVER 或第三方同步模式写入主表
  -> 重建 extendList 附属信息，兼容 schema 字段 key 映射
```

相关实现入口：

| 入口 | 说明 |
|---|---|
| `BasicMaterialImportHandler` | 公共导入处理器 Bean，配置名为 `basicMaterialImportHandler` |
| `MaterialServiceImpl.executeCommonImport` | 解析 `basic_material` 导入数据，支持 `ADD`、`UPDATE`、`COVER` |
| `MaterialServiceImpl.syncToThirdParty` | 调用接口平台默认编码 `basic_material_sync` 出站同步 |
| `MaterialServiceImpl.pullFromThirdParty` | 调用接口平台默认编码 `basic_material_pull` 拉取并写入 |
| `InternalMaterialIntegrationController` | 接口平台内部编排控制器，负责导出物料、调用平台配置、回写基础数据 |
| `IntegrationMaterialSyncFeignClient` | 接口平台调用 Basic 模块的内部 Feign 合约 |

公共导入模板配置、附属字段结构表、按钮权限和默认接口编码由 `Forgex_Doc/数据库/脚本与修复/20260512_material_import_sync_upgrade.sql` 补齐。该脚本会创建 `basic_material_extend_schema`、为 `basic_material_extend_config` 补齐 `material_type`，并写入 `fx_excel_import_config`、`fx_excel_import_config_item`、`sys_menu` / `sys_role_menu` 和接口平台默认 API 配置。

## 供应商主数据链路

供应商主数据位于 `Forgex_Basic` 模块，前端页面位于：

```text
Forgex_MOM/Forgex_Fronted/src/views/basic/supplier/index.vue
```

核心实现分层：

| 层级 | 说明 |
|---|---|
| `SupplierController` | 暴露分页、详情、新增、更新、删除、导入导出、生成租户、发起审查等接口 |
| `ISupplierService` / `SupplierServiceImpl` | 负责供应商主表、详情、联系人、资质、租户生成和工作流联动 |
| `BasicSupplier` | 供应商主表实体 |
| `BasicSupplierDetail` | 供应商扩展详情 |
| `BasicSupplierContact` | 供应商联系人 |
| `BasicSupplierQualification` | 供应商资质 |

新增 / 更新链路：

```text
前端供应商弹窗
  -> 校验供应商编码或自动生成配置
  -> 调用 supplierApi.create / supplierApi.update
  -> 后端保存主表、详情、联系人、资质
  -> 刷新 FxDynamicTable 列表
```

供应商新增弹窗使用公共 `BaseFormDialog`，并在业务调用处开启 `maskClosable`。该行为只作用于供应商页面，不改变公共弹窗默认的复杂表单保护策略。

供应商生成租户链路：

```text
POST /basic/supplier/generate-tenant
  -> SupplierServiceImpl.generateTenant
  -> SysTenantFeignClient.create 创建 SUPPLIER_TENANT
  -> TenantInitServiceImpl.initTenant 异步初始化
  -> 写入管理员账号、sys_user_tenant 租户绑定、管理员角色和菜单授权
  -> 回写 basic_supplier.related_tenant_code
```

供应商租户管理员账号使用租户编码而不是供应商名称生成，规则为 `admin_{tenantCode 去除非字母数字并转小写}_{tenantId 后4位}`，避免中文供应商名称导致账号不可预期。认证服务登录时会先按 `sys_user.account` 校验密码，再读取 `sys_user_tenant` 返回可选租户，因此初始化必须同时创建账号和租户绑定。历史环境如存在供应商租户但缺少账号或绑定，可执行 `Forgex_Doc/数据库/脚本与修复/20260512_supplier_tenant_login_fix.sql` 补齐。

## 计量单位链路

计量单位采用“类型树 + 单位主数据 + 换算关系”三表模型：

| 表 | 说明 |
|---|---|
| `basic_unit_type` | 计量单位类型树，维护类型编码、类型名称、父 ID 和层级路径 |
| `basic_unit` | 计量单位主数据，按类型维护单位编码、单位名称和备注 |
| `basic_unit_conversion` | 计量单位换算关系，表示 `1 源单位 = conversion_value 目标单位` |

计量单位三张业务表随 `Forgex_Basic` 默认主数据源存放在 `forgex_admin`；公共表格配置、国际化提示等公共配置仍存放在 `forgex_common`。旧版单表 `basic_unit` 升级时会按租户创建 `DEFAULT/默认类型` 并回填 `unit_type_id`，避免列表接口查询新字段时报错。

后端实现位置：

```text
Forgex_MOM/Forgex_Backend/Forgex_Basic/src/main/java/com/forgex/basic/material/controller/BasicUnitController.java
Forgex_MOM/Forgex_Backend/Forgex_Basic/src/main/java/com/forgex/basic/material/service/impl/BasicUnitServiceImpl.java
Forgex_MOM/Forgex_Backend/Forgex_Common/src/main/java/com/forgex/common/api/dto/UnitConvertRequestDTO.java
Forgex_MOM/Forgex_Backend/Forgex_Common/src/main/java/com/forgex/common/api/feign/BasicUnitConversionFeignClient.java
```

删除保护规则在服务层统一执行：类型下存在子类型或单位时禁止删除；单位存在源或目标换算关系时禁止删除。换算配置保存按源单位执行全量替换：前端提交的多行关系会保留或更新，未提交的源单位旧关系会被删除。

计量单位分页查询由 `UnitPageParam` 接收条件，`BasicUnitServiceImpl` 使用 `unitTypeId`、单位编码、单位名称和单位类型名称组合筛选。单位类型名称会先查询当前租户下匹配的 `basic_unit_type`，再按匹配到的类型 ID 过滤 `basic_unit`；如果没有匹配类型，列表返回空结果。

公共换算方法使用严格模式。调用方传入实体数据、目标单位编码、实体内单位字段名、单位字段类型 `ID/CODE` 和待换算数字字段名数组。服务会查询源单位、目标单位与直接关系；缺少直接关系时允许使用反向关系并执行除法。同单位直接返回原值。单位、字段、关系缺失或字段非数字时抛业务异常，计算使用 `BigDecimal`，不做默认四舍五入。
