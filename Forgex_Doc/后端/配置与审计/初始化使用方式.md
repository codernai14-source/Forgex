# 系统初始化使用方式

> 分类：后端 / 配置与审计
> 版本：**V1.0.0**

## 源码与前置条件

入口是 `Forgex_Sys/.../InitController.java` 的 `/init/status`、`/init/apply`，网关外部路径通常为 `/sys/init/status`、`/sys/init/apply`。初始化会清空 admin 库中的租户、用户、角色、菜单及绑定表，必须在备份并确认是首次部署后执行。数据库和 Nacos 配置应先可用，Redis 也必须可用来取得初始化锁。

## 基础调用

```ts
import http from '@/api/http'

const status = await http.get('/sys/init/status')
if (status.data?.firstUse) {
  await http.post('/sys/init/apply', {
    initialPassword: 'ChangeMe9!',
    pwdStrength: 'normal',
    passwordStore: 'bcrypt',
    captchaEnabled: true,
    captchaMode: 'image',
    defaultTenantName: '默认租户',
    defaultTenantCode: 'default',
  })
}
```

项目的 `http` 封装可能已经解包 `R<T>`；若直接使用 Axios，请按响应中的 `code === 200` 判断成功，不能把 `HTTP 200` 当成业务成功。

## 多租户和角色示例

```json
{
  "initialPassword": "ChangeMe9!",
  "pwdStrength": "high",
  "passwordStore": "argon2",
  "tenantNames": ["默认租户", "演示租户"],
  "defaultTenantName": "默认租户",
  "addCustomerTenant": true,
  "customerTenantName": "客户A",
  "addTest": true,
  "addDev": true,
  "roleTester": true,
  "roleDeveloper": true,
  "userTenantBinds": [{"account":"test","tenants":["演示租户"]}],
  "userRoleBinds": [{"account":"dev","tenant":"默认租户","roleKey":"developer"}]
}
```

`tenantNames` 只按名称匹配；绑定中写不存在的账号、租户或角色时会被跳过，不会自动创建。`initialPassword` 必须满足选择的策略，且首次登录用户会被标记为必须改密。

## 推荐用法与错误处理

- 推荐先调用状态接口，再只允许管理员在确认备份后提交一次；提交按钮应在请求期间禁用。
- `INIT_PASSWORD_INVALID`：检查长度、数字、大小写和符号要求；`high` 至少 8 位并要求四类字符。
- `INITIALIZING`：已有进程持有 Redis 锁，等待锁释放后再查询状态，不要并发重试清库。
- 初始化成功但登录失败：检查 Nacos 数据源、密码存储配置及 `security.crypto.*` 是否写入目标配置库。
- 菜单为空：确认种子 SQL/模块表存在；租户创建链路依赖主租户 `sys` 模块作为复制模板。
- 当前源码没有 dry-run、撤销和进度查询接口；需要这些能力时应新增独立任务模型，不能在页面自行猜测进度。
