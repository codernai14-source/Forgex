# 数据字典与日志实现逻辑

> 分类：后端 / 配置与审计
> 版本：**V0.8.5**
> 更新时间：**2026-08-12**

本文档说明字典配置、标签样式、缓存与日志审计在后端中的实现方式。

## 字典能力

`DictServiceImpl` 承担字典树、按类型取值、按路径取值、国际化标签解析等职责。

### 关键字段

| 字段 | 说明 |
|---|---|
| `dict_type` | 字典类型 |
| `dict_code` | 字典编码 |
| `dict_value_i18n_json` | 多语言显示值 |
| `tag_style_json` | 标签样式 |
| `tenant_id` | 租户归属 |

### 查询链路

```text
本地缓存
  -> Redis
  -> 数据库
  -> 回写缓存
```

字典查询默认带租户和语言维度，未命中时回退到 `tenant_id = 0`。

## 标签样式

前端 `DictTag` 会直接消费后端返回的 `tag_style_json`，因此字典既承载枚举值，也承载展示配置。

## 日志能力

### 登录日志

登录成功、失败、登出都通过专门服务异步记录，便于审计认证行为。

登录日志写入 `history` 数据源的 `sys_login_log` 表。登录失败通常发生在选择租户之前，因此失败记录使用 `tenant_id = 0` 或空租户表示公共审计事件；后台登录日志列表和导出会临时跳过 MyBatis 租户拦截，并手动限定为“当前租户日志 + 公共失败日志”，避免失败登录日志被当前租户过滤条件隐藏。

登录失败原因在写入前通过 `LoginFailureReasonResolver` 统一转换为中文展示文案；列表查询和导出也会对历史英文原因做同样转换，保证已存在的 `password incorrect`、`account or password is empty` 等记录在后台显示为中文。

登录日志中的 IP 归属地由 `IpLocationService` 使用 `ip2region` 离线库解析，库文件位于 `Forgex_Common_Infra/src/main/resources/ip2region/ip2region_v4.xdb`。解析逻辑不依赖公网接口；解析失败返回“未知”，本地地址返回“本地”，内网 IPv4 返回“内网”。

### 操作日志

业务操作一般通过注解和 AOP 方式自动记录模块、方法、请求参数、响应结果和耗时。

## 与其他能力的关系

- 与国际化：字典值按 `LangContext` 解析
- 与 Redis：依赖二级缓存与失效广播
- 与前端：支撑状态标签、下拉框、动态表格渲染

## 用户名自动填充

后端公共模块提供 `@AutoFillUsername` 注解和 `AutoFillUsernameAspect` 切面，用于在 Controller 返回结果中根据用户 ID 自动填充用户名字段。展示对象需要保留原始用户 ID 字段，例如 `createBy`，并新增展示字段 `createByName`：

```java
private String createBy;

@AutoFillUsername(userIdField = "createBy")
private String createByName;
```

切面会遍历统一返回对象、集合和分页 `records`，收集所有待转换用户 ID 后通过 `/sys/user/info/username-map` 批量查询，再回填到对应姓名字段。该机制只补展示字段，不改写 `createBy`、`updateBy` 等审计字段本身。

实现上同时兼容分页对象实现差异、父类继承字段，以及 Feign/JSON 反序列化后用户名映射 key 变成字符串的情况，避免列表页只拿到 ID 却无法回填姓名。
