# 系统初始化实现逻辑

> 分类：后端 / 配置与审计
> 版本：**V1.0.0**

## 源码位置

- HTTP 入口：`Forgex_MOM/Forgex_Backend/forgex-admin/forgex-admin-sys/Forgex_Sys/src/main/java/com/forgex/sys/controller/InitController.java`
- 主流程：同目录 `service/impl/InitServiceImpl.java`
- 新租户初始化：同目录 `service/impl/TenantInitServiceImpl.java`
- 参数与状态：`domain/param/InitApplyParam.java`、`domain/vo/InitStatusVO.java`

## 主流程

`GET /init/status` 读取配置键 `sys.init.status`，返回 `firstUse` 和 `usageCount`。配置不存在时按首次使用处理。`POST /init/apply` 使用 `@DSTransactional(rollbackFor = Exception.class)` 包住主流程，并先用 Redis `sys:init:lock`（2 分钟 TTL）防止并发初始化。

执行顺序如下：

1. 写入 `login.captcha`、`security.password.policy`、`security.login.failure`；密码存储为 `sm4`、`aes`、`rsa` 时生成对应密钥；同时生成 SM2 传输密钥并写入 `security.crypto.transport`。
2. 从刚写入的密码策略读取初始密码并校验长度、数字、大小写、符号要求；不合规返回 `INIT_PASSWORD_INVALID`。
3. 临时开启 `TenantContextIgnore`，按子表到父表删除角色菜单、用户角色、用户租户、菜单、模块、角色、租户、用户，保证重建时不受租户过滤影响。
4. 创建默认租户及参数中的附加租户，再创建 `admin` 以及可选的 `test`、`dev`、自定义用户。
5. 根据 `userTenantBinds`、`userRoleBinds` 建立绑定；未提供绑定时，用户绑定默认租户，`test/dev/custom` 按角色开关分配角色。
6. 为默认租户创建 `sys`、`basic`、`approval` 模块、菜单和按钮权限，并把菜单授权给管理员角色；同时创建 C 端工作台数据。
7. 写入 `sys.init.status={usageCount:1,initCompleted:true}`，返回 `R.ok(true)`；异常由事务回滚，锁在 `finally` 中释放。

## 租户创建后的流程

`TenantInitServiceImpl.initTenant` 另建 `sys_tenant_init_task` 任务，按 0、10、30、40、50、60、70、100 更新进度。它复制主租户的 `sys` 模块和菜单，按租户类型及 `perm_prefix` 规则过滤，再创建管理员角色、管理员账号、用户租户/角色绑定和角色菜单绑定。主租户账号固定为 `admin`，其他租户账号为 `admin_{tenantCode}_{tenantId后4位}`；初始密码来自 `security.password.policy`，并在插入前调用授权用户数检查。

## 二次开发边界和现状

- 新安全配置应在 `writeSecurityConfigsToCommon` 增加，并同步配置类和初始化测试。
- 新种子菜单应在 `seedDefaultPermissionData` 的对应模块方法加入，同时维护角色授权列表。
- 修改清库顺序必须评估外键和事务数据源；该方法是破坏性操作，只能用于首次部署或明确的重置场景。
- 当前接口只返回成功/失败，没有任务 ID；长时间初始化的进度应接入 `SsePushService` 或改为异步任务后再开放。
- `TenantInitServiceImpl` 的任务记录和菜单复制已实现，但跨节点幂等、失败重试和大菜单量性能仍需在真实数据库验证。
