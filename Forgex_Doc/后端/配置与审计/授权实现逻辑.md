# 软件授权实现逻辑

> 分类：后端 / 配置与审计
> 版本：**V1.0.0**

## 源码位置

- Controller：Forgex_MOM/Forgex_Backend/forgex-admin/forgex-admin-sys/Forgex_Sys/src/main/java/com/forgex/sys/controller/LicenseController.java
- 核心校验：Forgex_MOM/Forgex_Backend/forgex-common/Forgex_Common_Infra/src/main/java/com/forgex/common/license/LicenseManager.java
- 配置模型：同目录 LicenseProperties.java、DeploymentProperties.java
- 指纹与载荷：MachineFingerprintService.java、LicensePayload.java、LicenseRuntimeInfo.java
- 签发工具：Forgex_Build/license-tools/issuer；现场导入工具：license-tools/request-client

## 运行流程

1. current() 优先读取内存快照，没有快照时调用 refresh()。
2. ensureRequestInfo() 从 {licenseDir}/request-info.json 读取申请信息；文件不存在或解析失败时，根据机器指纹、实例码、主机名生成并尝试写回。
3. refresh() 读取 {licenseDir}/license.lic 和 Ed25519 公钥（优先配置项，其次 public-key.base64），授权文本按 payload.signature 两段 Base64Url 解码。
4. 验签成功后比对客户码和机器码，检查生效时间、到期时间及宽限期，生成 LicenseRuntimeInfo 并缓存。
5. 状态可能为 VALID、EXPIRING_SOON、GRACE、EXPIRED、INVALID、UNLICENSED。授权开关关闭时直接返回有效并标记“授权校验已禁用”。

授权载荷中的 maxUsers、maxTenants 在 checkUserLimit、checkTenantLimit 中执行；限制为 null 或负数表示不限制，限制为 0 表示禁止新增。初始化和租户初始化会在插入用户前调用用户数检查，其他业务是否检查取决于调用方。

## 接口与文件契约

- GET /license/status：当前状态、客户码、机器码、版本、配额、宽限期、文件路径和最近检查时间。
- GET /license/request-info：现场申请信息。
- GET /license/logs：读取 historyFileName 指向的历史 JSON，不存在或解析失败时返回空列表。
- POST /license/refresh：重新读文件、验签并替换内存快照。
- 网关通常加 /sys 前缀；Controller 本身只声明 /license。

## 二次开发边界与未完成项

- 变更签名算法必须同时修改 Java LicenseManager.verifySignature 和 C# KeyMaterialHelper/签发服务，并保留版本兼容策略；不能只替换公钥文件。
- 机器码覆盖、授权目录、预警天数等来自配置类，应通过配置注入，不要在业务代码写死路径。
- 当前连接状态是单进程内存缓存，服务重启后会重新读盘；没有在线授权服务器或自动续期协议。
- 控制中心的“导入授权”最终应把文件放入配置的 license 目录并调用刷新；文件权限、备份和多实例同步需要部署脚本保证。
