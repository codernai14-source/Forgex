# 消息模板

> 分类：后端 / 配置与审计  
> 版本：**V1.0.0**

## 功能定位与源码

模板管理源码：`Forgex_MOM/Forgex_Backend/Forgex_Sys/src/main/java/com/forgex/sys/controller/SysMessageTemplateController.java`、`service/SysMessageTemplateService.java`、`service/impl/SysMessageTemplateServiceImpl.java`、`validator/MessageTemplateValidator.java`；实体为 `SysMessageTemplate`、`SysMessageTemplateContent`、`SysMessageTemplateReceiver`。前端 API 是 `Forgex_MOM/Forgex_Fronted/src/api/message.ts`。

模板配置、公共模板复制和模板发送属于同一消息模板功能，但发送由消息服务链路执行，模板服务本身只持久化配置。

## 管理接口与接入示例

```ts
import { saveMessageTemplate, sendByTemplate } from '@/api/message'

await saveMessageTemplate({
  templateCode: 'TASK_CREATED', templateName: '任务创建通知', templateVersion: '1.0',
  messageType: 'NOTICE', bizType: 'TASK', status: true,
  receivers: [{ receiverType: 'USER', receiverIds: [1001] }],
  contents: [{ platform: 'INTERNAL', contentTitle: '新任务：{taskName}',
    contentBody: '任务 {taskName} 已由 {creator} 创建', linkUrl: '/workflow/task' }],
})

const count = await sendByTemplate({
  templateCode: 'TASK_CREATED', receiverUserIds: [1001, 1002],
  dataMap: { taskName: '采购审批', creator: '张三' }, bizType: 'TASK',
})
console.log(count.data)
```

管理路由为 `/sys/message-template/*`，发送路由为 `/sys/message/send-by-template`。前端 `http.ts` 会统一补 `/api`、携带 Cookie 并解包 `R<T>`。

## 数据模型和完整流程

主表保存 `templateCode`、名称/多语言 JSON、版本、消息类型、业务类型、状态和租户；内容子表按 `platform` 保存标题、正文、多语言 JSON、链接；接收人子表保存 `ROLE/DEPT/POSITION/USER/CUSTOM` 和 JSON ID 列表。保存时 Validator 要求编码和名称（普通文本或多语言 JSON）非空；Service 在一个事务中保存主表，更新会先删除旧子表再重建。`publicConfig=true` 把目标租户解析为 0，公共模板不能被公共租户再拉取。

发送时以 `templateCode` 读取当前租户模板，使用 `receiverUserIds` 或单个 `receiverUserId` 解析收件人，用 `dataMap` 替换正文变量，再进入站内消息投递链路。`dataMap` 键必须与正文占位符一致；当前模板服务不会提前校验缺失变量，也没有平台投递回执。

## 公共模板、多租户与读取

```ts
import { pullPublicMessageTemplate, pageMessageTemplate, getUnreadSummary, getUnreadMessages, markMessageRead } from '@/api/message'
await pullPublicMessageTemplate() // 按 templateCode 新增或覆盖当前租户
const page = await pageMessageTemplate({ pageNum: 1, pageSize: 20, status: true })
const summary = await getUnreadSummary()
const unread = await getUnreadMessages(20, 'MESSAGE')
if (unread.data?.[0]) await markMessageRead(unread.data[0].id)
```

## 推荐用法和错误处理

- `templateCode` 使用稳定的大写下划线编码；更新时带 `id`，公共模板请求显式传 `publicConfig: true`。
- 编码冲突：检查目标租户/公共租户范围，读取详情后带 ID 更新。
- 名称为空：提供 `templateName` 或合法 `templateNameI18nJson`。
- 发送数量为 0：检查模板状态、`INTERNAL` 内容、收件人 ID 和 `dataMap`。
- 公共拉取无变化：公共租户无模板或当前租户已是最新；返回值是变更数量。
- 删除残留：服务会事务删除主表及两个子表，检查租户上下文和 `publicConfig`。

## 二次开发边界与未完成能力

新增平台必须同时扩展内容配置、实体、发送适配器和前端平台枚举；新增接收类型需扩展保存层与发送方解析。当前没有严格 JSON 变量校验、并发编辑乐观锁和第三方平台投递回执；后续应增加模板占位符解析器、版本号校验、幂等发送键和投递状态表。多语言解析失败目前可能回退到普通文本或首个可用值，不能把回退当作严格校验。
