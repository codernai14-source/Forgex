# 软件授权使用方式

> 分类：后端 / 配置与审计
> 版本：**V1.0.0**

## 源码与接入方式

后端接口在 LicenseController，网关外部路径通常为 /sys/license/*。授权目录由 DeploymentProperties.licenseDir 决定，默认文件名来自 LicenseProperties：request-info.json、license.lic、public-key.base64、历史文件。签发端只保留私钥，客户部署目录只放公钥和授权文件。

## 基础查询

```ts
import http from '@/api/http'

const status = await http.get('/sys/license/status')
const requestInfo = await http.get('/sys/license/request-info')
const history = await http.get('/sys/license/logs')
console.log(status.data?.status, status.data?.remainingDays, requestInfo.data?.machineCode)
```

授权文件替换后调用刷新：

```ts
const refreshed = await http.post('/sys/license/refresh')
if (refreshed.data?.valid !== true) {
  throw new Error(refreshed.data?.message ?? '授权不可用')
}
```

## 现场签发和导入

1. 在客户运行实例调用 request-info，保存返回内容为 request-info.json；也可使用 Forgex_Build/license-tools/request-client/FxLicenseRequest 的 generate-request 命令。
2. 将申请文件交给签发端 FxLicenseIssuer 或 FxLicenseGenerator，根据客户码、机器码、版本、模块、用户/租户上限和宽限天数生成 license.lic。
3. 将签发出的 license.lic 与客户部署对应的 public-key.base64 放入授权目录；可使用 request-client 的 import-license 或控制中心导入。
4. 调用刷新接口并检查 signatureValid、customerMatched、machineMatched 和 status，再重启或继续服务。

示例命令（路径需按环境替换）：

```powershell
dotnet run --project Forgex_Build/license-tools/issuer/FxLicenseGenerator -- `
  issue --request-info D:/forgex/license/request-info.json `
  --private-key D:/issuer/private-key.pkcs8.base64 `
  --output D:/forgex/license/license.lic `
  --max-users 100 --max-tenants 10 --grace-days 30
```

## 推荐用法与错误排查

- 生产环境把私钥限制在签发机，客户机只部署公钥；授权文件和历史文件纳入备份但不要提交到代码仓库。
- UNLICENSED：检查 licenseDir/license.lic 是否存在且进程用户可读。
- INVALID/授权签名校验失败：公钥与签发私钥不匹配，或授权文本被换行、截断；重新导出原文件。
- 客户码不匹配/机器码不匹配：必须用同一实例生成的 request-info.json 签发，不能手改字段。
- GRACE：授权已过期但仍在载荷的宽限天数内，应尽快换发；过期后状态变为 EXPIRED。
- 达到用户或租户上限：按 LicenseManager 调用方的计数查询确认实际统计口径。
- request-info.json 写入失败时会退化为内存对象，重启后可能重新生成；应检查目录权限。
