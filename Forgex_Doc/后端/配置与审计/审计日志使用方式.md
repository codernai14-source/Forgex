# 审计日志使用方式

> 分类：后端 / 配置与审计
> 版本：**V1.0.0**

## 源码与接入方式

在需要审计的 Controller 或 Service 方法上添加 Forgex_Common_Infra 的 OperationLog 注解。必须填写 module、menuPath、operationType，可选 detailTemplateCode 和 detailFields。切面会自动采集租户、用户、请求、响应、耗时和异常。

## 基础示例

```java
@OperationLog(
    module = "sys",
    menuPath = "/system/user",
    operationType = OperationType.ADD,
    detailTemplateCode = "USER_CREATE",
    detailFields = {"account", "username"}
)
@PostMapping("/create")
public R<Long> create(@RequestBody UserSaveParam param) {
    Long id = userService.create(param);
    return R.ok(id);
}
```

detailFields 先从 R.data 或返回对象读取，再从方法参数读取，支持 JavaBean 属性路径和 Map 键。使用 R.ok/R.fail 保持统一状态码，切面会据此设置 success。

## 跨服务和查询示例

Basic、Report 等没有本地 SysOperationLogRecorder 的服务会自动使用 RemoteOperationLogRecorder，通过 Feign 调用 Sys 的 /operationLog/internal/record。查询当前租户日志：

```ts
import http from '@/api/http'

const page = await http.post('/sys/operation-log/page', {
  current: 1, size: 20, module: 'sys',
  operationType: 'ADD', startTime: '2026-09-01 00:00:00'
})
const verify = await http.post('/sys/operation-log/verify-chain')
```

导出请求体是 {tableCode, query}，响应为文件流，不能按普通 JSON 解包。

## 推荐用法与错误排查

- detailTemplateCode 必须和当前租户、module、operationType 对应的 SysOperationTemplate 一致；模板不存在时仍会保留结构化字段但没有 detailText。
- 不要把密码、私钥、完整令牌放入 detailFields；虽然切面会脱敏，减少敏感数据更可靠。
- 查不到日志：确认请求携带租户上下文及 sys:operation-log:view 权限；跨服务还要检查 Feign 路由和内部接口鉴权。
- 链校验失败：检查是否有人工修改、迁移截断或按错误租户查询；verify-chain 只校验当前 TenantContext。
- 审计写入失败不会让主请求失败，需查看 Sys/远程 recorder 日志并补充可靠投递。
- export 返回 401/403 时分别检查登录态和 sys:operation-log:export；时间格式错误会被忽略为无时间条件。
